# AgentBridge 产品约束

本页是当前产品定位、范围与设计约束的统一入口。整体功能状态见[产品设计](product-design.md)，实际接入能力见[接入矩阵](agent-integration-matrix.md)，下一阶段安排见[项目路线](project-plan.md)。约束描述应达到的行为，不代表全部功能已经实现或发布；源码、受控测试、真实原生调用、独立机器与发布包证据分别记录。

## 1. 定位与用户体验

AgentBridge 帮助用户连接不同厂商、设备和会话中的既有 Agent，在原来的工作环境中发现、调用和观察获准目标，同时保留原生工具、账号、模型配置及已有知识资产。

- 首批聚焦跨 Windows、WSL、Linux 工作的多 Agent 开发者；Personal Agent、自建 SuperAgent 可作为上层消费者。
- 默认体验应覆盖发现、接入、授权、一次调用和结果读取。可定制能力通过合理默认值与按需配置提供，不要求用户先理解插件体系。
- 日常需求从原生 Agent 发起；Bridge 桌面承担连接配置、授权、观察、诊断和原执行恢复。CLI/MCP 入口不以专用聊天界面、小队或看板为前提。
- 模型、供应商、原生工具权限和 Agent Loop 继续由原 Agent 管理。Bridge 不新建模型 API 层，不自行决定任务拆分、调用目标或业务验收。
- 本地和用户自有环境优先。现有本机、WSL、SSH 路径继续使用；私有 Relay 等是可选拓展，公有云和复杂 P2P 不构成必需依赖。

## 2. 核心、可选扩展与当前非目标

| 层次 | 职责与约束 |
| --- | --- |
| 互联核心 | 身份与获准发现、明确目标寻址、认证授权、调用台账与幂等、Session 关联、状态与结果、必要交互控制、事件补读、资源准入和审计 |
| 接入基础设施 | MachineHost、daemon、必要 worker、原生适配、受控 SSH 安装维护与配置；执行节点保留原生凭据和运行环境 |
| 可选协作层 | 主从、对等、Issue、事件驱动等协作规则；现有 TeamSpace/TeamAutomation 保持兼容，业务工作流暂停扩张；新模式逐项设计授权和生命周期 |
| 可选工作区 | Markdown/Obsidian、Issue、Kanban 等外部工作事项与资料映射；可以完全不启用，不成为普通调用的前置条件 |
| 可选上下文与记忆扩展 | 上下文来源解析、结果回写、候选知识贡献、外部记忆检索；抽取、审核和存储可交给外部工具，不默认复制全量会话 |
| 当前非目标 | 自有 Agent Loop、模型管理、智能选目标、自动故障转派、任意远程 Shell、强制任务平台、通用文件同步、多租户/云高可用、完整插件市场 |

核心职责集中，同时保留必要的可靠性实现。小队界面、业务验收、记忆抽取可以关闭；身份、授权、原请求恢复和 unknown 保护不能作为可关闭的体验选项。

## 3. 身份、会话与调用

| 概念 | 区分与要求 |
| --- | --- |
| 机器 / Runtime / Agent | 环境、执行入口、逻辑 Agent 分开；登记说明不生成执行能力。Agent 的稳定身份不允许在途任务自动换端点 |
| 调用方主体 / 上下文 / 凭据 | 主体表达获准身份，上下文承载调用归属，凭据用于认证；凭据轮换、新入口或新上下文不自动继承其他任务权限 |
| Session / Invocation / Work Item | Session 可承载多轮调用；一次调用可以不关联工作事项；业务工作事项可关联多次执行，不能替代原 Task 终态 |
| Context / Memory | Context 为当前任务提供必要材料；Memory 是经授权维护的长期知识；摘要不自动成为事实或授权 |

上述概念映射到现有对象，字段与状态沿用[数据模型](data-model.md)和[协议](protocol.md)。Invocation 是调用生命周期概念，不要求再建一套与 requestId、delegationId、taskId 并行的任务引擎。

首阶段由 Bridge 请求目标 Runtime 新建会话，或沿已记录、可核对且获准的原绑定恢复会话：

1. 新建明确目标上的会话，保存原请求与原生 Session 的关联。
2. 续聊要求上一轮已知终态、原调用归属/端点/目录绑定和当前授权有效，且目标支持 Resume。
3. 任务执行中或结果 unknown 时恢复观察，只查询原 ID 和事件游标，不提交替代执行。
4. Attach、Steer、任意历史会话导入及跨主体接管分别评估，不作为首阶段完成条件；Resume 不等于 Attach。

连接一个已有原生服务并创建新的 Session，不等于接管它的活动会话。关闭观察入口、停止自有后台、取消原生任务分别按[资源归属契约](iterations/I08/interconnect-caller-contract.md#资源归属与停止范围)处理。

## 4. 可靠性与授权底线

- 提交意图先持久化，回应未知时查询原 requestId/operationId，不通过新 ID、节点、目录别名或 Session 重跑。
- 控制请求的 confirmed 与任务 succeeded/cancelled 分开。取消无法确认时保留 unknown，不承诺所有原生入口均能确定取消。
- 能力声明、现场探测、原生实际执行与当前授权分别核对；不支持的会话或交互能力明确拒绝，不能静默退化成新会话。
- 先授权再发现，读控核对原归属。A 可以调用 B，不自动授权 B 调用 C；递归委派和自动事件执行需另行明确范围。
- 首片可采用串行、忙时拒绝与会话隔离。目录占用仅为资源准入，文件系统隔离由原生环境落实。
- 事件游标用于补读和去重，事件重放不再次触发业务执行。事件不含无权读取的正文、私有绑定或凭据。
- 不把 IP 可达当作身份，不默认上传原生账号和密钥；授权变化即时影响新调用和当前读控资格。

## 5. 上下文、工作区与记忆

最小上下文交接属于调用体验：明确任务、约束、仓库版本、必要摘要、日志和产物来源。引用必须说明所属环境、版本、访问范围及如何读取；路径存在不证明目标可读，引用也不证明文件已传输。

首条跨机构建可采用两端已有同一提交、干净工作树和已配置目标目录的前提，使用必要日志正文或已验证可读的引用。未提交修改、二进制产物和大文件传输不隐式同步；缺材料时如实报告。

Workspace 是可选的外部工作事项/笔记系统，不等于 Runtime 的执行目录。后续映射可关联一项或多项外部资源，但本轮不新增必填字段；外部状态不取代调用台账，Markdown 写入需版本核对和冲突处理。

Memory 扩展只共享获得授权的必要内容，保留来源、范围、版本、时间及删除/失效机制；候选知识与已审核知识分开。Basic Memory、Mem0、Graphiti 等仍是候选，不代表已接入。已有 Agent 可直接使用外部记忆工具时，先复用该路径，再判断是否需要 Bridge 适配。

## 6. 扩展与 Profiles

扩展按职责拆分，优先稳定已有适配契约，通过真实第二种用例检验抽象；不一次构建八类动态插件宿主。现有静态、经源码审核的注册仍有效，通用第三方加载/隔离尚未实现。

扩展必须说明能力、版本、所需权限、依赖、生命周期和失败行为；沿统一调用与授权接口工作，不直接改原台账或读取其他 Agent 凭据。同进程加载不构成权限隔离，外部插件信任与隔离方案须单独验证。

Profile 作为配置组合方向，应提供默认可用的 MCP 调用与授权体验，允许关闭 Workspace/Memory。具体名称、配置格式与迁移方式未冻结；导出不包含密钥，不自动迁移机器信任或旧任务读控权。原生工具 profile、Bridge 运行实例 profile 与未来体验预设应明确区分。

## 7. 开发顺序与完成判据

1. 复用现有互联核心，优先完善新建、同会话续聊、等待交互、结果读取与原请求恢复；首选验收场景为 Windows Codex → 独立 Linux OpenCode，WSL 证据单列。
2. 验证必要上下文真正到达，再由调用方明确选择另一个 Agent 继续分析。
3. 验证一个可选 Markdown 工作区集成，确认关闭它仍能正常调用。
4. 根据实际需求评估 Memory、更多协作模式、Profiles 与协议扩展；不得以数量或插件市场替代主链路验收。

完成标准包括首次成功耗时与人工步骤、原入口工具实际可见、目标正确、版本/目录正确、原 Session 保持、交互可处理、unknown 不重复执行和授权隔离。成功正文之外还要保留失败、跳过、截断及未测项；源码、实机、独立服务器和包交付不得相互替代。

首阶段各项实现及实测证据见[当前范围核对](iterations/I08/current-scope-audit.md)；会话生命周期的既有决策保存在[互联核心边界](iterations/I08/interconnect-boundary.md)和[调用方契约](iterations/I08/interconnect-caller-contract.md)。
