# Pi

Bridge桌面提供配置、审计和原执行恢复；本页列出的执行/续聊等是后台适配能力。日常需求从原生Agent会话提出，或由获准主Agent委派。

## 如何连接

Bridge 调用 Pi 原生 CLI 的 JSON / print 接口，并关联其原生会话文件。任务使用 Pi 在目标机器上的账号、模型与项目配置。

先在目标机器确认 Pi 原生 CLI 可以运行，再在Bridge检测Pi节点、配置独立MCP；从Pi原生会话工作，或由获准主Agent委派给该节点。

## 支持的功能

支持直接会话、新建与续聊、结果读取、取消和普通被委派。原生小队成员、Bridge 内权限或结构化表单回复未适配。当前公开alpha.68支持Pi独立MCP配置管理。

接收普通委派不要求 Pi 主动调用 MCP，但主 Agent 需要具备获准的 Bridge 调用通路。

## 续聊与会话文件

续聊需要找到原生会话文件。文件丢失或候选不唯一时，Bridge 会拒绝继续，避免把需求发送到错误的会话。不要通过创建新别名假装恢复了旧会话。

公开alpha.68会在发送前核对会话文件保存的目录与原上下文目录一致；目录缺失或被改为其他目录时，保留历史并拒绝续聊。请核对原文件和目录，不要新建同名会话替代。

当前源码还修复了目录别名在回复时被误判的问题：指向同一可用目录的链接可保留原会话；缺少目录信息或链接目标改变时不能判为成功。这项回复校验修复尚未包含在公开alpha.68中。

详见[任务与会话](../sessions.md)与[原生 Agent 功能对照](index.md#功能对照)。

## 原生 MCP 配置

包含此适配的版本可在 Pi 节点的配置窗口添加或移除 AgentBridge MCP，要求 Pi 1.4 及以上的 1.x 正式版。管理用户目录下的 `mcp.json`；你设置 `PI_CODING_AGENT_DIR` 时使用该目录。更改后在 Pi 执行 `/reload`，再核对原生列表。项目配置覆盖或原生禁用请在 Pi 中核对，Bridge 不会重新启用。

切换用户目录时，先移除原接入，再为当前目录添加；移除只清理原目标，其他 MCP 与原任务保留。公开alpha.60提供十个经典工具，包含`list_connectable`、`connect_agent`和`disconnect_agent`。Pi1.4.0的Linux/Windows原生客户端已核对目录和连接策略；仍需在自己的环境重新加载并核对，组件连接成功不代表模型已调用或已获准委派。
