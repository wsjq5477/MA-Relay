# OpenCode

当前alpha.68的Bridge桌面提供配置、审计和原执行恢复；本页列出的执行/续聊等是后台适配能力。日常需求从原生Agent会话提出，或由获准主Agent委派。

连接检查先识别原生健康接口，再核对相应版本的 API。若显示“待检查原生 API”，请按该节点的协议或健康原因检查原安装；这时不能作为可用执行目标。重新扫描会刷新观察到的版本，已有上下文不会自动切换到另一安装。历史未确认操作须继续查询原操作，不能通过重复接入解除。

安装检查沿用已选的原安装；显示版本只说明该入口可以调用，真实模型回复仍需在原生工具中核对。

若提示原生服务已退出，先检查目标机器的内存及原生工具状态。修复资源问题后，支持恢复的后台可在显式接入时启动原上下文服务；更新Windows客户端不会自动更新SSH后台。未确认操作仍应先查询原操作，不能删除记录或重复提交需求。

## 如何连接

Bridge 使用原生 CLI 启动 OpenCode 服务，再通过原生 HTTP API 管理会话、任务和交互。CLI 与 API 是同一条接入链的两个环节。

在目标机器安装并配置 OpenCode，先确认它可独立执行任务，再在“接入配置”检测。当前适配包含 1.x 与 2.x 协议分支；工具能被发现不代表任意版本的全部交互都受支持。

## 支持的功能

直接会话、新建与续聊、结果读取、取消、普通被委派、通过 Bridge MCP 主动调用，以及已适配的权限和结构化输入请求。

具体交互依赖原生版本所提供的 API。日常权限或提问请在OpenCode原生入口处理；恢复已有Bridge执行时，在“执行审计”显式选择“处理这条原执行”，再按适配能力回复并核对原任务。

## 服务与配置

原生服务在执行机器上运行，模型、供应商、项目和原生权限仍由 OpenCode 管理。Bridge 负责服务连接与任务控制，不要求各机器的 Agent 互开网络端口。

## MCP 与协作

可使用托管会话的 MCP 通路，也可在“接入配置”的 OpenCode 行点击“配置”，管理原生 MCP 连接。配置变更后，应让相应原生服务重新载入配置。

详见[MCP 与连接授权](../connections.md)与[任务与会话](../sessions.md)。
