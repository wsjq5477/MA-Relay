# OpenCode

## 如何连接

Bridge 使用原生 CLI 启动 OpenCode 服务，再通过原生 HTTP API 管理会话、任务和交互。CLI 与 API 是同一条接入链的两个环节。

在目标机器安装并配置 OpenCode，先确认它可独立执行任务，再在机器页面检测。当前适配包含 1.x 与 2.x 协议分支；工具能被发现不代表任意版本的全部交互都受支持。

## 支持的功能

直接会话、新建与续聊、结果读取、取消、普通被委派、通过 Bridge MCP 主动调用，以及已适配的权限和结构化输入请求。

具体交互依赖原生版本所提供的 API。出现权限或问题表单时，在 Bridge 提供的控件中回复，再等待原任务状态更新。

## 服务与配置

原生服务在执行机器上运行，模型、供应商、项目和原生权限仍由 OpenCode 管理。Bridge 负责服务连接与任务控制，不要求各机器的 Agent 互开网络端口。

## MCP 与协作

可使用托管会话的 MCP 通路，也可在“机器与 Agent”的 OpenCode 行点击“配置”，管理原生 MCP 连接。配置变更后，应让相应原生服务重新载入配置。

详见[MCP 与连接授权](../connections.md)与[任务与会话](../sessions.md)。
