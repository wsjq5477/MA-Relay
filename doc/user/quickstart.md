# 快速开始

## 准备原生 Agent

在任务实际执行的机器上安装并配置原生 Agent，先确认它自身能正常工作。AgentBridge 沿用它的账号、模型、工具和项目配置，不另建模型供应商配置。

[原生 Agent 适配](agents/index.md)列出每个入口的执行方式和支持功能。DSH 的服务入口有单独的[连接说明](agents/dsh.md)。

## 添加机器并发现 Agent

打开 AgentBridge 的机器页面，使用本机或添加 WSL / SSH 机器，再执行工具检测。Windows 和 WSL 是不同运行环境，各自的命令、目录与配置分别发现。

选择已发现的 Agent，确认机器在线、可执行程序或服务连接可用。安装检测只说明找到了工具；第一次实际任务才能确认原生账号和模型连接是否可用。

## 发起第一条任务

在目标 Agent 的会话中选择该机器上的工作目录，输入需求并发送。查看执行状态和原生输出；完成后继续输入，可在同一原生会话中续聊。

项目目录属于当前会话。换机器或换工具不会自动迁移原生会话，工作目录也不会变成所有节点的全局配置。

遇到权限请求时，支持直接回复的入口会显示相应控件；其他入口需要在原生工具里处理。[各入口的权限与取消能力](agents/index.md#功能对照)有所不同。

## 开启 Agent 间协作

在关系页面选择支持调用 Bridge MCP 的主 Agent，连接允许接收委派的目标，保存授权，再在需要协作的会话中启用协作。关系保存只建立授权，不会立即开始任务。

独立运行的原生 Agent 可在“机器与 Agent”对应工具行点击“配置”，管理 Bridge MCP 连接。当前支持 Claude Code、Codex 和 OpenCode 的原生 MCP 配置管理；详见[MCP 与连接授权](connections.md)。

## 查看结果与继续工作

任务页显示状态和结果，会话页保留消息与原生会话关联。取消后要等待状态核对；出现“未知”时查询原任务，避免重复发送。[任务与会话](sessions.md)说明这些状态的含义。

需要更换 Windows 程序时，先在“设置 → 后台运行 → 停止后台并退出”结束旧后台。远端机器后台需要在对应机器的维护入口单独更新。
