# 机器与 Agent

机器表示原生程序真正运行的环境。Windows 本机、一个 WSL 发行版和一台 SSH 主机分别拥有自己的目录、配置与后台状态。

## 发现与连接

在机器页面选择目标机器并运行检测。Bridge 使用该环境当前可用的原生程序发现 Agent，显示版本及连接状态。工具升级或修改命令路径后，再次检测可以发现新的入口。

找到可执行文件或已安装的服务配置，只能说明工具存在；完成连接仍需要可运行的程序、在线后台，以及有效的原生配置。

| 环境 | 准备事项 | 工作目录 |
| --- | --- | --- |
| Windows 本机 | 安装并配置 Windows 原生工具 | 使用 Windows 可访问的目录 |
| WSL | 在目标发行版安装工具，确认后台可用 | 使用该发行版中的目录 |
| SSH | 添加主机并完成远端后台安装与连接 | 使用远端主机上的目录 |

## 配置 Agent

各Agent行在“开始会话/接入”右侧提供“配置”。打开后固定当前机器和Agent：Claude Code、Codex、OpenCode显示Bridge MCP接入；DSH Desktop/Web显示服务地址与连接token；其他工具显示原生配置说明。无需再到全局设置选择机器。修改期间保持弹窗打开，完成后关闭会返回原配置按钮；配置不会自动发起会话。

## 服务型入口

OpenCode 由 Bridge 调用 CLI 启动原生服务。DSH Desktop / Web 则连接用户已经运行的认证服务，需要在所属机器的DSH节点右侧点击“配置”，保存服务根地址和连接凭据；[DSH 章节](agents/dsh.md)给出步骤。

发现未配置的 DSH Desktop / Web 时，应补齐服务连接，不需要为了接入桌面版或网页版再配置 headless 模型账号。命令行中的同名 Distributed Shell 不属于 DeepSeek Harness。

## 原操作待核对

出现“原操作待核对”时，点击旁边的“查看”直接定位到原操作卡片，或打开“设置 → 未确认操作”，查看来源机器、Agent、操作类型及查询结果。这里也列出接入、断开等管理操作；它们与任务执行分别核对。点击“查询原请求”只核对原操作，查询失败或尚无确定收据时继续保留占位。

待核对期间仍可扫描和打开“添加 Agent”查看工具；实际接入、变更和相关执行继续受保护。DSH Desktop / Web仅缺少连接时显示“待配置服务连接”，点击该Agent右侧的“配置”打开服务连接弹窗。

## 状态与维护

机器离线时先恢复后台连接，再查询原任务状态。离线不会把已有请求变成新的执行，也不会自动转移到另一台机器。

后台维护被拒后，机器可能显示“已断开”，卡片会给出拒绝原因和重新连接的入口。若同时提示“原操作待核对”，先点“查询原机器操作”核对原操作，不要另起一次升级。重新连接只恢复查看和读取原结果，不会重发任务；重开程序不会自动恢复，需要点一次“重新连接”。若提示升级仍未生效，确认没有运行、等待或待核对的任务后，再做一次“后台维护 → 升级后台”。

维护进行中，弹窗会显示“正在上传 / 解包 / 校验”和进度，机器卡片上也有一行同样进度；确认之后若显示“已发送维护指令，等待远端切换”，表示指令已经交给远端、正在等它报告结果，程序会自动核对原操作直到出现成功或失败原因，此时按钮暂时不可点是为了避免重复下发同一次维护。核对一直没结果时，按上一段的“查询原机器操作”和“重新连接”处理。

“后台维护”弹窗把三件事分开显示：**上次维护结果**只是上一次维护留下的结果（若当前实际版本已经和程序一致，会明确写“无需升级”，并不代表这次失败）；**维护前置门禁**是实时阻塞项，每条都可以“按原 ID 查询”核对，只查原操作、不重发任务；只有**仍有未确认收据、同时没有任何任务或 Agent 在运行、并且确实有可升级目标**时，才会出现“我已确认这些操作不会再运行”勾选和“确认升级（保留未确认收据）”按钮。勾选意味着你确认这些操作不会再运行：升级会保留这些未确认收据（不会删除），但**任务或 Agent 只要还在运行、等待或状态未知，就没有越过入口**，必须先按原 ID 处理。

若某台机器的旧后台一直因为一条无法查清的旧收据拒绝维护，正确做法是先按上面的门禁列表逐条“按原 ID 查询”；只有在没有任何任务/Agent 阻塞、并且你确实确认那条旧操作不会再运行时，才使用越过升级。不要用越过去跳过仍在运行的任务。

升级本机桌面程序不会更新 SSH 主机上的后台。需要更新时，进入对应机器的维护入口，完成后重新检测连接。更换工具入口也不会把旧会话自动迁移到新可执行程序。
