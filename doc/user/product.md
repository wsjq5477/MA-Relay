# 产品功能

AgentBridge 把分散在本机、WSL 和 SSH 机器上的原生 Agent 连接起来。用户在桌面选择执行目标、管理会话和授权关系；Agent 在授权范围内发现目标、委派工作并查询结果。

## 核心对象

| 对象 | 用途 | 与其他对象的关系 |
| --- | --- | --- |
| 机器 | 原生程序和目录所在的运行环境 | 一台机器可以发现多个 Agent |
| Agent 节点 | 一种工具在某台机器上的执行入口 | 使用原生配置，按自身能力接收任务 |
| 会话 | 用户与某个 Agent 的连续对话 | 绑定实际原生会话与本次工作目录 |
| 任务 | 一次提交及其执行状态、结果 | 可来自用户输入或获准的委派 |
| 关系 | 哪个 Agent 可以调用哪个目标 | 保存授权后，实际调用才发起任务 |
| 小队与工作 | 围绕一个工作目标组织成员、任务板与授权交接 | 用户管理访问，主角色负责分工与业务验收 |
| 公共工作材料 | 协作中的文档、任务与消息视图 | 与某个 Agent 的私有对话分开管理 |

## 可以完成的工作

- 发现和连接 Windows 本机、WSL、SSH 上的原生 Agent。
- 发起任务、查看输出与结果、在同一原生会话续聊。
- 对支持的入口回复权限或输入请求，取消并核对任务状态。
- 保存 Agent 间授权关系，让支持 MCP 的调用方委派任务。
- 组织小队工作、任务板与产物版本，在用户授权的预算内跟进工作。
- 查看公共工作材料，选择版本生成只读选材包，并导出本机副本。

[接入总览与功能对照](agents/index.md)列出各入口的支持范围。功能可用还取决于当前安装版本、目标机器在线状态与原生工具配置。

## 原生配置的归属

模型、供应商、Skill、原生工具和内部记忆由原 Agent 负责。Bridge 负责连接、路由、授权与任务观察，不把这些配置复制成另一套模型管理层。

用户选择的工作目录属于会话，关系只表达调用授权；节点和关系不绑定固定模型或项目。

## 工作界面

[机器页面](machines.md)用于发现与维护连接，[会话页面](sessions.md)用于直接工作，[关系页面](collaboration.md)用于授权协作，[工作材料](materials.md)用于阅读与整理共享内容。Agent行“开始会话”右侧的“配置”管理该节点的[MCP 连接](connections.md)或DSH服务；设置页管理主题、后台与原操作恢复。
