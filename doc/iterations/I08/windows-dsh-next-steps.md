# 下一版工作计划：让 Windows 用户用 DSH 完成第一次真实委派

2026-11-23 · 执行结果见[开发与验收](windows-dsh-first-use-acceptance.md)。产品实现基线为 `ac393cf`，首用说明见 `8e34c2f`。公开 ACP 便携版 `8b69f71` 已支持会话和取消，工具权限回复从 `ac393cf` 起才有源码实现。上轮已完成产品评审和文档纠错。[产品评审](product-readiness-review.md) · [审批现状](acp-permission-reply.md)

**本轮交付目标**是给已经在用 DSH 的 Windows 用户一份可试用的便携 EXE 和一页与该版本一致的快速开始。用户只看这页，就能从原生会话找到获准目标、委派一个只读任务、核对答案，并在关闭窗口后找回同一任务。

## 先做的工作

| 顺序 | 要做什么 | 交付物与通过条件 |
| --- | --- | --- |
| 1. 固定候选包 | 从包含 ACP 审批实现的本地主干，用 `powershell -File scripts/build-local-exe.ps1` 生成 Windows x64 便携版。记录提交、EXE 版本、文件位置及 DSH 版本。 | 能凭记录找到同一份 EXE。后续各项注明所用包；修复导致换包时，最终候选重新走首用流程。[打包脚本](../../../scripts/build-local-exe.ps1) |
| 2. 从首次打开走到正确答案 | 使用没有 Bridge 连接和授权记录的 D 盘隔离配置。Windows **DSH NEXT 原生会话作调用方，单独接入的 DSH ACP 节点作目标**。沿用已获准的 DeepSeek 账号，按快速开始扫描、接入、授权，再从原生会话列出允许调用的目标。 | 用户在原生会话读回目标文件中的正确文字，并能在「执行审计」找到对应的目标和任务。记录从打开 EXE 到窗口可用、再到首次正确结果的耗时，以及需要人工操作或额外指导的步骤。[快速开始](../../user/quickstart.md) · [DSH 两种入口](../../user/agents/dsh.md) |
| 3. 验证续聊、关闭与恢复 | 上一轮明确完成后，要求目标沿原会话回忆刚读到的文字。关闭 Bridge 窗口再打开，使用原任务 ID 查询结果，沿原事件游标继续读取。另用独立的可取消任务核对取消。 | 追问产生新一轮，目标及原生 Session 保持一致。重开前后原结果一致，恢复观察新增执行数为零。取消操作的收据和原任务最终状态分别可见。[任务与会话](../../user/sessions.md) |
| 4. 验证真实工具权限 | 先只读核对上一轮停在 `unknown` 的原任务。独立的新验收场景使用无敏感内容的测试文件，以及原生端确实会询问的操作。从「执行审计 → 处理这条原执行」回复。 | 能看到原生权限询问和工具信息，「仅允许本次」只对应本次请求。拒绝用独立场景核对。分别记录回复收据、工具实际行为和任务结局。未出现询问就记为未验证；原未知任务只按原 ID 查询。[审批实现和已有失败记录](acp-permission-reply.md) |
| 5. 修复卡点并交付 | 按上面第一次失败的位置修。发现不到节点查扫描；原生会话看不到目标查 MCP 加载及定向授权；任务已派发却没有结果则查对应 DSH Profile、原生事件及任务绑定。文案写清用户当下能采取的动作。 | 在最终候选上复验修复点及首条委派。交付该 EXE、与其一致的快速开始、一份记录通过与未通过场景的验收报告。支持表按该版本的原生证据更新。[接入矩阵](../../agent-integration-matrix.md) |

现有快速开始用 DSH 调用 Claude Code 举例。本轮候选使用同一安装下分别登记的 DSH NEXT 和 DSH ACP，验收时核对两者的节点标识和授权方向。把这条路径通过实测的步骤写回候选版快速开始，再交给首次使用者。

**首条任务示例**。事先在目标目录的短文本里写一行临时标记。给调用方说：“请通过 AgentBridge 把读取这个文件的任务交给已授权的 DSH ACP，返回第一行原文和任务 ID。”提示中只给目标和文件路径，预期答案由验收者保留。核对主会话答案、目标原任务正文和文件三者一致。追问时请它只依据上一轮会话回答。

**记录方式**。每个场景记下候选版本、机器与入口、起止时间、人工步骤、期望与实际结果、原任务/会话/操作的关联以及脱敏证据位置。下载耗时和首次打开后的操作耗时分别填写；本地交付的候选标注“本地取得”。已有的 22.3 秒是配置完成后一次任务的耗时。实测若需要配置原生账号、人工解释或修改文件，都计入首用记录。开发、测试配置和日志落在 D/E 盘，公开材料使用脱敏标识。

## 完成到什么程度可以交给谁

- **Windows 开发者试用**：同一候选的首次委派、同会话追问及重开查询都有真实结果。权限或取消若仍未得到原生证据，在试用说明中逐项标明限制。
- **面向新用户自助试用**：请一位未配置过 Bridge 的目标用户，只看最终版快速开始完成上述首次委派，记录需要帮助的地方。修复会卡住用户的问题后再核对。对外承诺的审批和取消须能在这份候选上演示。
- **公开发布**：本地包交付和验收结果单独登记。用户确认本地包并明确要求发布后，再走 GitHub 发布流程。
