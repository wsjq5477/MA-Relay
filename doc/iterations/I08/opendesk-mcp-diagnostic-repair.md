# OpenDesk 日常 MCP 诊断条目恢复

核对日期：2026-10-22，19:08–19:10（Asia/Shanghai）。日常 Windows Bridge 后台为 alpha.46，Windows Node v24.18.0。本轮是用户私有配置修复，无产品代码、EXE、发布或远端部署变化。

## 原因与处理

用户原生 OpenDesk 会话调用 `list_agents` 报 `fetch failed`。只读核对发现：OpenDesk 的 AgentBridge 条目仍指向 `external-verify` 诊断端点，其地址为本机端口 1；它不等于 Bridge 已登记并启用的正式条目。实际调用该诊断端点复现 `fetch failed`，同时调用正式端点返回 HTTP 200 和 7 个获准节点。因此本次不是 alpha.46 后台未运行，也不是模型配置错误。

按[原生配置冲突保护规则](../../user/agents/opendesk.md)，没有自动认领该未登记条目。用户明确同意“允许备份并替换”后，在用户私有配置目录备份原文件并核对字节一致；仅替换已确认的 AgentBridge 诊断条目，复用现有正式授权。写后核对条目与正式登记一致，其他原生设置和其他 MCP 条目保持原值。备份和完整配置不进入仓库、报告或日志。
