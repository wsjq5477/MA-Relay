# AgentBridge 产品设计与可用性评审

2026-11-23。评审对象为本地 `master` 的产品源码 `ac393cf` 和 GitHub 的 Windows x64 ACP 便携预发布 `0.6.0-alpha.76.local.20261123.acp`（`8b69f71`）。首批用户是已经在用原生 Agent 的多环境开发者。产品要让用户在自己的 Agent 里选择获准目标、委派工作、读回结果，并能在断开后找回原执行。[产品约束](../../product-constraints.md) · [公开版本](https://github.com/wsjq5477/MA-Relay/releases/tag/v0.6.0-alpha.76.local.20261123.acp)

**结论：具备面向开发者小范围试用的 Alpha 条件。面向新用户自助上手的公开 Beta 尚缺同版验收，稳定版的跨机承诺也未达到。** 两个原生 Agent 之间已经完成过有用的工作。当前最大的产品缺口，是还不能给拿到这个 EXE 的用户一条经过同版验证、从首次启动一直到原生会话读回结果的路径。

## 设计文档质量

产品约束写清了首批人群、原生会话这个日常入口，以及 Bridge、模型和上层协作各自承担的职责。协议把“已收到批准或取消”和“任务已结束”分开，工程人员能据此处理断线和重复点击。按模块保留设计、测试和历史失败，也能追溯一个能力最早在哪个环境有证据。[产品约束](../../product-constraints.md) · [调用方契约](interconnect-caller-contract.md)

评审发现四处直接影响用户选择的问题：快速开始和桌面说明导向上一个 Setup；整体设计仍指导在桌面输入新需求；用户表把本地才有的 ACP 审批当成公开包能力；OpenDesk CLI 在一张表中显示可主动调用，而实证只到导出 MCP 配置片段。本轮校正这些入口，并对齐专用入口数量和通用 ACP 的统计口径。[快速开始](../../user/quickstart.md) · [桌面说明](../../../desktop/README.md) · [流程设计](../../product-design.md#4-用户的完整操作路径) · [用户能力表](../../user/agents/index.md#功能对照)

设计可支撑继续研发。作为发布依据，仍缺以同一份 EXE 为起点的一组用户任务和通过记录。主设计与协议仍保留多轮历史，读者需要跨文档拼接某一版的现状。历史测试资料的部分链接在指定归档目录也无法解析，影响独立复核。[归档核对](current-scope-audit.md#文档归档核对)

从产品价值看，已有的编码委派和结果交接证明这条路径能解决真实任务。所查材料还没有独立新用户自行走通或持续使用的数据，因此无法判断日常使用率。旧版文档站浏览器脚本仍断言 8 个入口和 alpha.34 的文案，只能解释对应版本的历史结果。[历史站点脚本](../../../desktop/tests/windows-doc-site.cjs)

首用还有一个具体障碍。Windows 上发现 DSH NEXT 并完成 Bridge 接入后，headless 的原生 Profile 仍可能缺少模型认证。用于本机验收的已有 DeepSeek 桌面账号需要在相应原生 Profile 显式启用。评估自助上手时，应把用户识别这个状态、找到正确配置、再拿到回答的步骤计入总耗时。[DSH 账号与入口说明](../../user/agents/dsh.md)

## 下一次产品验收应交付什么

1. **首用与成功。** 用同一份 Windows 候选 EXE，保留原生账号，以尚未配置 Bridge 的环境从下载、打开、扫描、授权开始。在真实主 Agent 中明确委派本机 DSH 读取已知内容，核对目标、结果和原 Task，再在原 Session 追问。分别记录到窗口可用和到首次正确结果的时间、人工步骤、失败与恢复。值应实测后再定门槛。
2. **遇到交互或中断仍能收尾。** 在含审批实现的同一候选中用真实 DSH 观察原权限询问、单次决定和独立的最终状态。关闭观察器再打开，从原 Task 和游标恢复。若结果未知，核对只查询原请求、原生执行次数没有增加，保留未确认的原任务。
3. **每条支持承诺都有对应证据。** 主推一个实测 Windows 组合。准备承诺 WSL 或 SSH 的版本时，逐条补目标机器、原生版本、已测操作和异常恢复。评估发布版时只采用其自身证据，每份包的下载、首次启动和真实任务分别登记。
