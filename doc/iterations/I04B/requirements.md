# I04B：Windows Claude 与 WSL OpenCode 的机器分层需求

日期：2026-10-09。用户已确认目标：同一 Windows 桌面窗口同时接入本机 Windows 的 Claude Code 与 WSL 的 OpenCode。本文件是本轮开发与验收基线，尚未通过的项目不能写为已交付。

## 交付目标

用户打开 AgentBridge 后，先看到这台 Windows 执行机器及已安装的 WSL 执行机器，再看到各机器发现的工具连接；选择项目后创建实例。在同一窗口中向 Windows Claude 实例、WSL OpenCode 实例分别提交任务、续问、查看历史，能够清楚辨认每项工作在哪里执行。

Windows 与 WSL 是独立执行机器，界面注明它们位于同一物理宿主。这里的实例指绑定项目与执行配置的长期对象；会话和每轮任务属于实例，不以运行进程或一次模型调用替代实例。

```text
这台 Windows 电脑                 WSL · Ubuntu（同一物理宿主）
└─ Claude Code 连接              └─ OpenCode 连接
   └─ Windows 项目实例              └─ Linux 项目实例
      └─ 会话 → 每轮任务               └─ 会话 → 每轮任务
```

## 可验收增量

| 增量 | 交付内容 | 进入下一增量的条件 |
| --- | --- | --- |
| B1：先有机器与工具 | 自动建立机器记录、扫描各自工具、分离工具连接与实例、导入既有 OpenCode | 没有任何实例时仍看见机器；发现工具不选择项目、不调用模型；旧记录完整可见 |
| B2：双机实例与看板 | 在指定机器创建项目实例；双宿主同时连接；按来源路由；总览、任务、会话聚合与筛选 | Windows 路径只进入 Windows；WSL 路径只进入选定发行版；同名实例及相同本地 ID 不串记录；切换视图不终止工作 |
| B3：真实使用与交付 | Claude 原生 CLI 文本、续问、取消、历史；OpenCode 原功能回归；故障隔离；更新 Windows 产物 | 两种工具各有真实两轮执行证据；取消确认与实际终态分开；单边故障不影响另一边；未确认操作不重发 |

## 需求与规则

| 编号 | 用户功能与业务规则 | 验收条件 |
| --- | --- | --- |
| M01 机器清单 | Windows 本机与安装的 WSL 发行版独立显示；机器名称、系统、可达状态、最后同步时间可读；机器不依赖已有 Agent 才出现 | 空配置显示 Windows 本机；WSL 探测失败保留 Windows；相同机器多次启动/刷新不重复建档；记录跨重启保留 |
| M02 工具发现与连接 | 在机器内扫描 Claude Code/OpenCode 安装路径和版本；连接表示选定工具可由该机器调用，不要求先选项目；自动使用可推导默认项 | 正确机器出现正确工具；发现/连接新增 Prompt 数为 0；无 Key、端口、是否启用等重复确认；安装缺失和通道失败有不同提示 |
| M03 项目实例 | 在已连接工具下选择项目，创建实例；名称、项目、原生角色、模型继承关系及启停状态属于实例；同一工具可有多个不同项目实例；模型默认继承，另提供可选的每实例覆盖 | Windows 项目保持 Windows 绝对路径；WSL 项目经映射后在目标发行版校验存在；错误发行版 UNC 拒绝；每个实例有唯一归属和独立会话；显式模型覆盖仅作用该实例，不写工具全局配置 |
| M04 多机器聚合 | 总览同时展示所有已登记机器及连接；看板/会话可按机器、工具连接、实例过滤；卡片始终提供来源机器、工具与项目 | 两个机器同时在线且任务可同时观察；改变筛选或导航不关闭后台通道、不取消任务；一边出错另一边记录继续刷新 |
| M05 精准路由与未确认恢复 | 提交、续问、详情、权限回复、取消及原请求查询固定路由到记录来源机器；写前持久化机器身份及原请求 ID | 两台机器即使本地 taskId、conversationId、requestId 相同也互不覆盖；不明回应按原机器查询，不能因当前视图或默认机器变化而改发 |
| M06 Windows Claude 最小可用 | 调用 Windows 本机安装的 Claude Code 原生 CLI，继承现有用户登录、供应商和默认模型；展示真实流式进度、回答、错误；按原 Session 续问；取消只作用于 Bridge 自己启动的执行 | 真实 Windows Claude 两轮保持同 Session；重开应用保留已落库历史；未登录显示原生登录指引；不索要新 API Key；不额外启动 WSL Claude |
| M07 工具能力可见 | OpenCode 原有权限/表单处理继续工作。Claude 权限回复、输入表单、取消和恢复按实际版本/协议能力提供；无法支持时界面明确说明 | 不显示不可用的“允许”按钮；不将原生权限拒绝伪装成成功；不自动添加 bypass/acceptEdits/broad allowedTools；模型和 Session 从原生事件确认 |
| M08 旧数据兼容与故障隔离 | 旧 OpenCode agentId 作为实例 backendId 原样保留，桌面公共 ID 增加机器前缀，补充 machine/connection 归属；保留任务、会话、原生 Session、请求及结果；每机器有独立连接和错误边界 | 升级后后端历史条数、原 ID、状态、每轮回答、Session 绑定丢失/错配数均为 0；迁移重复运行不重复生成实体；一边离线另一边仍可正常完成任务 |
| M09 交付与证据 | 更新便携 Windows 程序、操作路径及本轮测试记录；自动合约与真实工具结果分开报告 | 根项目及桌面工程检查通过；给出可运行产物的实际路径；真实通过、未测试、受原生能力限制分别列明 |

模型覆盖是可选高级配置，不成为首次连接必填项。原生默认模型因账号无权限或模型下线而失败时，展示原生错误，并允许只为当前实例指定该账号可用模型；不得为解决一个实例而修改 Claude/OpenCode 全局模型或要求用户重新录入 Key。会话续问仍核对原执行配置绑定，不静默把已有会话切换到另一个模型。

## 指标

| 指标 | 验收目标 | 测量方式 |
| --- | --- | --- |
| 无推理发现 | 启动、扫描、连接、实例创建和历史浏览新增原生 Prompt 数 = 0 | 假 CLI/服务调用记录；真实会话记录只读前后对比 |
| 双机路由 | Windows/WSL 各 10 次确定性任务，共 20 次，目标命中 20/20，串路由 0 | 两个独立宿主夹具调用记录与来源键 |
| ID 隔离 | 至少一组 task/conversation/request 同 ID 在两个机器共存；查看、续问、取消、原请求查询全正确 | 固定冲突夹具，分别核对两端调用次数和持久行 |
| 真实闭环 | Claude 与 OpenCode 各完成 1 个两轮会话；各自 Session 绑定一致、跨工具混用 0 | 原生事件、Bridge 任务/会话记录及实际窗口 |
| 重复执行 | 同请求重入 10 次仅一次原生提交；不明响应重开/切换界面后自动补发次数 = 0 | 原生调用计数、请求日志及待确认记录 |
| 迁移 | 升级及再次迁移后历史内容差异和丢失均为 0 | 升级前后快照/数据库内容比对；只忽略新增归属元数据 |
| 单边故障 | 分别模拟 Windows 宿主退出、WSL 通道失效；另一边可读并完成 1 个任务 | 独立夹具/隔离实例；不停止用户日常服务 |
| 观察延迟 | 每机器各 20 次确认状态变更，正常连接下界面可见 p95 ≤2 秒；冷启动另记 | 后台确认至前端可见时间差；不含模型回复耗时 |

## 本轮边界

范围限本机 Windows 与本机安装的 WSL，暂不接外网/远程电脑、不做主 Agent 调度、跨工具转移同一原生会话、并行 worktree 编排或账户配置编辑。

同一实例仍串行执行。同一物理目录通过 Windows 与 WSL 的不同路径访问时属于共享资源，不能因机器 ID 不同就宣称并行写入安全；支持已知路径的占位校验，未覆盖的共享目录别名必须在交付限制中说明。

切换机器视图必须保持运行。关闭窗口和宿主异常时，已确认终态继续保存；不能核实仍在执行的任务保持未确认/unknown，既不自动补发 Prompt，也不未经原生证据显示取消成功。WSL OpenCode 已有后台执行能力不应退化；Windows Claude 后台保活/异常恢复按实际实现证据报告。

设计依据：[Multica 的机器与运行环境](https://multica.ai/docs/daemon-runtimes)、[Agent 与运行环境的区分](https://multica.ai/docs/agents-create)、[Claude Code 程序化调用](https://code.claude.com/docs/en/headless)、[Claude CLI 参数](https://code.claude.com/docs/en/cli-reference)。这是本项目的需求设计，不表示依赖工具的每项能力已在本机验证。
