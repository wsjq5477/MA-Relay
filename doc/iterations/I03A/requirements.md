# I03A 需求规格：CLI 首次配置与可使用闭环

日期：2026-10-08。
状态：按用户最新要求，当前继续使用 CLI，浏览器相关方案暂缓。用户已批准开发；I03A CLI 功能已实现，验收记录见 report.md，待用户签收。
依据：[交互方案](../../interaction-plan.md)。[模块设计](design.md)、[开发计划](development.md)、[测试计划](testing.md)按同一范围维护。

## 1. 交付目标与范围

在 Linux/WSL 本机运行 agentbridge。首次在终端向导中配置现有 OpenCode；之后在同一终端查看已连接 Agent、提交需求、观察结果、处理原生权限和输入。后台服务不要求另开常驻终端。

I02 前台命令保持兼容；以下终端向导、交互菜单与后台服务为本轮实现的默认入口。

| 项目 | 本轮范围 |
| --- | --- |
| 交互 | 普通终端中的中文向导、列表、菜单、任务观察和回复；使用 @clack/prompts 的勾选、方向键选择和进度提示，不开发全屏 TUI |
| 系统/连接 | Linux/WSL 本机 Hub；托管本机 OpenCode，或连接本机已有原生服务 |
| Agent | 真实 OpenCode 2；Mock 标记测试，不计真实验收 |
| 数量 | 多个连接；同一设备的同一真实工作目录最多一个启用连接 |
| 执行 | 每任务新原生会话；保留幂等和资源串行规则 |
| 配置 | 新建、已有 I02 配置原位导入、原生模型继承/覆盖、默认执行目标 |
| 延期 | 浏览器与 Web 控制台暂缓；连续会话、取消和完整恢复为 I03B；后续看板范围在 I04 再确认；委派为 I05；正式跨设备部署为 I06 |

OpenCode 仍是首版默认执行工具及未来主 Agent 候选，模型由用户选择。I03A 不实现协调者的智能路由、委派和汇总。固定目录不是新增文件系统沙箱，资源占位只保护 Bridge 自己派发的执行。

## 2. 交付入口与用户路径

| 入口 | 行为 | 实现状态 |
| --- | --- | --- |
| agentbridge | TTY 中：无连接自动发现并勾选，有启用连接先自动连接再进入菜单 | 已实现默认行为 |
| agentbridge setup [--dir PATH] [--import PATH] [--advanced] | 配置向导或预览后原位导入已有配置 | 已实现 |
| agentbridge agents / run / task / native | 保留现有单次命令、JSON 和脚本使用；默认实例可省去反复指定配置 | 已保留并扩展默认配置与交互 |
| agentbridge agents --watch | 观察 Agent 状态变化 | 已实现；单次 agents 仍只显示查询快照 |
| agentbridge service status或stop --dir PATH | 查询/明确停止本实例后台 | 已实现 |

原 up 保留开发/验收用途。非 TTY 调用默认入口不进入交互或自动配置；显示明确用法，脚本继续使用显式子命令。

首次：启动 → 自动扫描 PATH/原生安装目录 → 空格勾选 → 回车自动保存并连接 → 自动只读检查 → Agent 概览/操作菜单。使用当前项目、继承模型、build 和后台托管；首个连接自动设默认。真实回复验证由用户主动触发。

日常：启动 → 查看连接和默认目标 → 输入新需求 → 观察工具与输出 → 同终端回复权限或输入 → 查看结果 → 返回菜单。退出交互不停止后台，重新进入只读取已有任务。

## 3. 八项需求

### F01 单终端入口与后台生命周期

- 无配置时可以进入终端向导，不先编辑 JSON 或手动启动 Hub/Edge。
- 默认使用本用户固定状态目录；同一实例只创建一份后台控制器、Hub/Edge，重复启动复用。
- 交互 CLI 连接后台后留在终端接收操作；退出客户端不停止后台、不取消原生任务。明确停止使用独立命令并说明影响。
- 单个 Agent 故障不让配置/状态入口失效。只能停止本实例拥有的进程，外部原生服务仍由其所有者管理。
- 旧 up 或无关进程占用同一数据/端口时提示冲突，不抢进程；不把后台化当作开机启动或自动恢复。

验收：同一实例并发启动 5 次仅一份后台；日常额外必需终端 0；退出交互后任务继续；外部服务不被错误终止。

### F02 终端首次向导、发现与导入

- 发现已实现 Driver 的工具，展示版本、路径及支持/不支持原因；发现可执行程序不等于已连接。
- 当前真实支持 OpenCode 2。其他工具不会因存在于 PATH 就获得已接入标记。
- 默认向导只要求空格勾选并回车；名称、已有工作目录、托管/已有服务、模型覆盖等手动配置在 --advanced 或高级设置中，敏感输入不回显。
- 高级模式草稿保存为停用，不启动原生服务。普通选中即保存并连接；再次进入自动连接已有启用项，包括旧 connectOnStart:false 配置，保留原 ID 和历史。
- 基础检查与真实执行分别显示。允许保存未验证配置；连接可用与模型已实际回复分开显示，不把元数据检查当真实回复。
- 导入先预览，确认后保留原 ID、凭据引用、数据库位置、历史和 unknown，占用时拒绝接管；不复制 SQLite，不静默改原生 Provider 配置。
- 配置缺失/损坏/版本不兼容或导入失败明确报错，原数据保持；无法确认旧未知任务资源时保守锁定待核对。

验收：不手改 JSON 完成首次接入；中断后可继续已保存草稿；导入后 ID、历史和未知占位丢失 0。

### F03 Agent 连接维护

- 支持在交互菜单添加、编辑、启停；Agent ID 和 Connector 绑定保持稳定，改名不换 ID，本轮用停用代替删除。
- 原生 Agent 默认 build，模型继承原生配置；其他原生 Agent 选择仅在实际接口契约验证后开放。
- 已有服务只允许本机回环地址，密码由后台受保护保存/引用。规范化真实目录，同目录的软链接、不同 ID/模型/端口不能绕过冲突。
- 只局部应用目标连接，不重启整个 Edge 影响其他任务。配置保存与应用分别显示 revision；旧版本并发修改拒绝。
- 有 queued/accepted/running、原生等待或 unknown 占位时拒绝改变目录、服务、程序、原生 Agent、模型、权限或身份绑定。名称和默认选择可改。
- 停用仅禁止新任务，保留既有执行、回复、历史和资源占位。执行配置变更使旧验证过期。

验收：两个不同真实目录可分别连接；修改空闲连接不干扰另一运行任务；busy/unknown 的执行配置修改和占位绕过均为 0。

### F04 分层检查与真实执行验证

- 只读检查分别展示安装/版本、目录、服务可达、认证和模型配置；目录中存在模型不等于真实调用通过。
- 真实验证由用户明确触发并说明会调用模型，建立可查询验证任务，遵守串行和请求幂等。
- 发出短小随机标记回复请求，不读取文件、不执行工具。原生禁止工具的权限约束必须先完成真实契约核验，不能仅靠提示词保证。
- 若不能保证禁止工具，不启用该验证方式，也不宣称 F04 通过，记录阻断。
- 实际回复/消息绑定、成功终态、随机标记一致且工具调用 0 才通过；记录配置指纹、实际模型、时间、Task/Session。
- 配置或继承模型变化使旧验证过期。拒绝、认证/额度、超时、断开分别提示，不自动换模型/Agent或重试 Prompt。
- 忙碌、停用和 unknown 时不发第二次验证；检查、列表和状态刷新不调用模型。

验收：两连接分别取得真实标记回复；未触发验证时模型调用 0；每次验证 Prompt 1、工具调用和文件改动 0；基础通过但 Provider 拒绝时能正确显示执行失败。

### F05 Agent 列表、默认目标与状态

- 交互概览和 agents 命令列出已配置连接，包括停用、离线；显示名称、工具、设备、目录、原生 Agent/模型及默认标识。
- 分开展示配置状态、连接状态、执行验证和工作状态，并显示检查时间。
- 工作区分空闲、执行中、等待授权、等待输入、unknown。unknown 不显示可接单。
- 单次 agents 是查询快照；交互任务观察/agents --watch 更新状态。更新失败显示旧时间，不将旧在线状态当当前确认，不把 Hub 故障当作没有 Agent。
- 默认 Agent 是本实例后续新任务的默认目标；不可用时说明原因，不静默换目标。默认变化不改已提交任务或等待请求。
- 菜单按实际能力开放，本轮不展示已实现主 Agent 协作的标记。

验收：所有配置项可见，状态与后台一致；默认变化只影响新任务；离线、失败、等待、unknown 可由终端输出辨认。

### F06 同终端单次任务与结果

- 在同一终端选目标、输入需求、观察执行、取得真实结果；提交前明确 Agent、工作目录和模型来源。
- 沿用 owner/allowlist、输入长度、requestId 去重和每任务新会话规则；不提供会话续接。
- requestId 在发送前持久化，重复提交复用 ID；不同内容冲突拒绝。响应不明只查询原请求，不自动重发。
- 展示真实工具摘要、输出/终态、等待信息和结果截断标记；接受回执不显示完成。
- 退出观察、切换菜单或重新进入任务只读查询，不取消、不重投；可按 Task ID或当前/最近任务重新观察。
- 原有显式 run/task 等单次命令仍适合脚本与 JSON 查询。

验收：真实分析、修改和实际测试均有证据；同 requestId 提交 5 次仅 1 Task/1 Prompt；重返自动新增 Prompt 0；两个新任务会话不同。

### F07 同终端权限与输入回复

- 任务观察遇到原生等待，在当前终端提示 Task/Agent、动作/资源或问题，直接允许单次同意/拒绝或输入答案，不要求另开终端和编辑 JSON 文件。
- 核验真实表单结构，至少支持一个真实原生文本输入；未知类型明确不支持，不猜答案结构；不提供永久授权。
- CLI 经本机受保护后台控制接口、Hub 授权、Edge 执行回复，原生密码/长期 token 不进入交互输出。
- Hub 校验 owner、Task/execution、Connector和原生绑定；Edge 再核对台账与该 session 当前 pending。
- operationId/指纹在原生写之前持久化；同一原生请求只允许一条待发送、不明或确认回复，不同操作 ID 并发也不二次写。
- 接收回复与任务完成分开；超时显示结果不明，不自动重发。过期、其他任务或已由原生 CLI 回复的请求拒绝。
- 停用不阻止旧任务回复；unknown 或不可达时禁用不安全操作。

验收：当前终端完成真实权限允许/拒绝及原生文本表单回复；同操作 5 次原生写 1；越权/过期成功回复 0。

表单原生合约与模型自主提问分别报告。真实原生表单 + 终端授权回复链为必验；模型未自主触发表单时标注未验证，不能冒充模型闭环通过。

### F08 持久配置、重返与异常/权限边界

- 后台持久化配置版本、默认目标、验证、任务/原生绑定、回复操作和真实资源占位；交互客户端不是权威执行状态。
- 完成历史重启后不变；未知执行保留 unknown，占位不因编辑、停用或导入解除。
- 旧未知资源优先由 native.workspace/旧配置回填，无法唯一定位则锁定待核对。
- 本机后台管理接口使用 OS 权限保护的 IPC，保留 Hub/Edge 身份验证、owner/allowlist及配置目录权限；本轮无 Web 会话、Cookie 或浏览器 API。
- 敏感输入不回显，终端/日志/IPC 摘要不输出原生密码或长期 token。写盘失败保留旧完整配置；应用失败不能显示已生效。
- 不提供 unknown 释放、自动重连对账、执行重试或自动迁移。旧 CLI 的查询/提交/观察兼容，停用限制同时约束所有入口。

验收：配置/默认/完成历史丢失 0；自动重投 0；未授权配置写/原生回复 0；长期凭据泄露 0。
