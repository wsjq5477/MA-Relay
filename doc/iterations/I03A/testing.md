# I03A 测试与人工验收计划

日期：2026-10-08。状态：**已实施，工程检查及真实 CLI 核心验收通过，待用户人工签收**。用户已明确当前继续使用 CLI，暂不考虑浏览器。本文件保留验收规格；本轮实际结果另见 [交付报告](report.md) 与第 7 节，不以计划表冒充通过证据。

## 1. 验收范围与证据口径

本轮验证 Linux/WSL、交互终端、Node、真实 OpenCode 2：首次启动、终端向导、连接检查、同一终端提交和观察单次任务、权限/文本表单回复与重新进入。允许同一 Edge 配置多个 OpenCode Agent，但同一设备的规范化真实工作目录最多一个启用连接，同一原生执行资源仍串行。busy 和 unknown 不能通过更换 Agent ID、模型、服务端口或目录别名绕过。每个新任务仍创建新的原生会话。

连续会话、协调者委派、取消、自动重连对账、unknown 释放、Windows 原生、远程 TLS 和完整历史看板不计入通过范围。退出 CLI 或关闭终端后后台任务继续执行，只证明后台生命周期，不证明中断恢复。一次性 `agents` 输出只是读取时的快照；实时观察需使用明确提供的观察模式，不能把普通列表承诺为自动刷新。

| 证据类型 | 可证明的内容 | 不能替代的内容 |
| --- | --- | --- |
| 离线服务与 CLI/IPC 合约测试 | 配置校验、终端状态、访问控制、重复请求和故障分支 | 真实 OpenCode 连接、模型调用、工具执行 |
| 真实原生接口合约探测 | OpenCode 2 的实际认证、权限/表单接口与终端回复链路 | 模型自主产生表单并继续完成任务 |
| 真实模型人工验收 | 同一终端提交到真实模型、实际工具调用、真实等待及结果 | 跨设备、其他 Adapter、多 Agent 协作 |

I02 证据仅作回归基线。不得把 I02 的手工配置、双终端操作或旧结果直接登记为 I03A 的首次向导与同终端交互通过。

## 4. 独立真实 OpenCode 人工验收步骤

交付入口：TTY 下 `agentbridge`（无配置进入向导，已配置进入菜单/列表）、`agentbridge setup [--dir PATH] [--import PATH]`、`agentbridge service status|stop --dir PATH`，均已实现并有核心验收证据。已有 `agents`、`run`、`task`、`native` 保持兼容；`agents --watch` 提供持续观察。准备和采证方法见 README 与真实验收脚本，未以直接调用后台替代终端向导和交互。独立观察者可只读核验记录/原生接口，其采证终端不计用户日常额外必需终端。

1. **准备独立样例。** 复制示例到临时目录，记录初始哈希及失败测试。新建隔离 Bridge 配置，沿用 OpenCode 已有认证，记录所选模型；将样例 edit 设为一次授权。
2. **首次启动。** 在一个终端运行入口，查看发现结果，空格勾选后回车自动连接，不询问名称/目录/模型/启用/是否启动；检查期间原生 Prompt 数不增加；记录终端向导摘要与后台进程所有权。
3. **验证执行。** 主动验证本轮随机标记，禁止读改文件和调用工具。核对实际回复、工具 0、哈希不变；设置默认目标并进入列表，未验证与通过必须区分。
4. **分析任务。** 同终端提交“只分析 multiply 的问题，不改文件”并观察。独立核对 Hub Task、原生 Session/User Prompt 与哈希；没有实际回答或发生修改不能通过。
5. **修改、等待与测试。** 同终端提交修复并测试，看到实际 edit 等待后一次允许。核对原生 edit/bash 及输出、multiply 改为乘法、add/测试文件保持，再独立运行样例测试。
6. **拒绝授权。** 独立样例新任务触发 edit 并在同终端拒绝，核对请求及无越权修改。最终行为如实展示，不能规定拒绝后模型必然失败。
7. **表单链路。** 尝试模型自主创建受控表单，终端填答后核对继续与结束。未触发则记“模型自主表单待验证”；真实原生接口创建的受控表单仅证明终端提示/单次回复合约，不能伪造模型提问证据。
8. **多连接、重复与重返。** 第二个不同真实目录独立完成随机标记验证，记录各自指纹/模型/Task/Session/回复、工具 0、文件修改 0，再分析并核对绑定。新 requestId 重复 5 次应为 1 Task/1 Prompt；忙碌目录的第二启用连接应拒绝。退出 CLI 再进入，默认/任务/结果保留，重复启动不新建 Prompt。
9. **异常与占位。** 新任务停在真实权限等待，终止本轮拥有的原生或后台服务，再启动入口。unknown、绑定和占位保持；刷新、重新启动、资源别名均不重投。不在本迭代尝试释放/恢复 unknown。
10. **清理与报告。** 只停止本轮拥有的进程，确认无关程序无影响。记录预期/实测、脱敏终端记录、Task/Session/User Message/Request 关联、独立文件/测试结果、Prompt/回复数、待验证项和失败原因。清理临时凭据，保留必要证据。

真实调用设总时限防止无限等待；超时登记失败或待验证，不因此重发 Prompt。模型耗时单独记录，Provider 不可用时不得用离线通过替代真实闭环。
