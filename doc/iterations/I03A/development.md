## 1. 交付顺序

I03A 按四个可演示增量开发，作为一个迭代验收：

1. **能配置并接入**：单 CLI 入口、后台启动、终端首次向导、发现/导入 OpenCode、默认目标和 Agent 列表。
2. **能区分连接与执行**：分项检查、显式真实验证、验证记录与配置过期提示。
3. **能完成真实任务**：同一终端提交、观察、permission/form 单次回复，取得真实回答与结果。
4. **能退出并重返**：终端退出后台继续运行，重返只查询；验证并发保存、去重、unknown 占位与受影响 CLI 回归。

增量演示不代表整体通过；最终按 testing.md 完成独立真实模型验收。

## 3. 关键实现门槛

- 先核验原生合约，再实现验证/表单；I02 edit ask 不证明 deny-all 或所有字段类型。
- 迁移保留旧数据；不复制正在写入的 SQLite，失败不创建空库掩盖问题。
- 保存和运行应用分开，用 revision/资源锁反映生效版本；不为改一个连接重启整个 Edge。
- 原生写前持久记账，Prompt/permission/form 不因网络问题自动重试；操作收据和任务终态分开。
- IPC 用 OS 权限保护的本机 socket，后台持凭据；任务经控制器→Hub→Edge 校验，密码不交给呈现层，不提供任意目标代理。
- 同本机真实目录占位跨 Agent ID，最多一个启用连接；busy/unknown 不因换 ID、停用或改默认释放。
- Clack 提示组件 普通提示/列表/菜单足够；先完成单次任务闭环，不引入全屏 TUI 或连续原生会话。
- 默认仅影响新任务，与未来智能协调者分别建模；本轮无 delegate、取消或自动恢复。

优先验证重复执行、错误关联、配置丢失和越权，不为简单字段展示写镜像测试。

D08 运行 lint/typecheck/test/build，并补充受影响 I01/I02 回归。D09 在隔离实例和目录完成真实终端验收，认证仍由原生工具管理。可控错误分支补充模型不稳定场景，但真实闭环必须有真实调用证据。

状态性能测后台已确认事件到交互观察或 `agents --watch` 刷新：20 样本 p95 ≤ 2 秒；单次 `agents` 只验收查询快照。心跳、检查和模型耗时单独记录。重复执行/越权用实际 Prompt 和原生写计数核验，不只看最后一个 Task。

测试报告初始 not_run。开发完成、原生合约通过、真实模型通过分别记录；未自主创建表单时，只报告合约和终端回复链通过，自主提问单列未验证。
