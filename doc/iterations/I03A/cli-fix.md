# I03A 用户试用后的 CLI 修复

日期：2026-10-08。状态：已实现，工程与新流程真实验收通过。

## 问题与改动

原向导默认保存草稿，用户选完进入菜单后仍未连接；发现逻辑藏在填写路径之后，主流程要求填写过多内部配置，列表主要显示 ID、版本和原生字段。

现在首次运行扫描 PATH、~/.opencode/bin 等位置，显示 OpenCode 版本和路径。用户空格勾选、回车即自动保存并连接；默认当前项目、继承原生模型、build、后台托管及文件修改逐次授权。模型/项目/已有服务等手动项放高级设置或 `agentbridge setup --advanced`。停用草稿仅在高级模式保存。

再次进入自动连接已有启用项，修复旧版 connectOnStart:false 的有效配置。菜单用方向键/回车，按连接名称和项目选择，多数单连接操作不再问 ID；历史任务通过列表选择。列表显示中文连接/工作状态与实际模型，失败显示原因，元数据可用与真实回复验证分开。

后台保留具体启动错误，重新连接可重试此前失败的启动；冷启动先等待只读模型目录初始化。连接和检查不调用模型。原生授权/表单依旧经 Hub→Edge 校验与双台账，不因交互简化取消执行保护。

交互组件参考 [OpenClaw 的 Clack 提示实现](https://github.com/openclaw/openclaw/blob/main/src/wizard/clack-prompter.ts)。没有复制其风险确认、浏览器或其他产品流程。

## 使用

退出旧菜单，重新运行 `agentbridge`，现有连接自动接入。新目录的首次连接按空格、回车完成。原生服务未配置模型时，先在 OpenCode 完成配置；Bridge 不自行改选提供方。I03B 连续会话/取消/故障对账继续实施，不能把本修复当整个 I03 已完成。
