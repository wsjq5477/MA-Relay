# I04D：模型恢复与会话记录修复

交付日期：2026-10-10。Windows 桌面版本：0.4.4。

## 问题与原因

用户日常 WSL OpenCode 实例没有模型覆盖，仍继承已停用的 opencode/exo-free。此前隔离验收使用了其他模型，未修复日常实例。因此工具连接在线，但模型实际回复失败；重新建会话仍会遇到同一错误。

会话页还默认显示连接验证记录，容易将诊断历史误认成实际需求。旧 WSL 摘要缺少 kind 和 items 元数据，需要兼容识别。模型失败记录即使已有原生 Session，也应先引导修复模型。

## 交付行为

- 正常会话列表与总览最近会话排除连接验证；会话页可勾选“显示连接验证记录”查看历史。关闭后退出当前选中的验证记录。
- 没有实际会话时显示新建入口；验证任务入口命名为“查看验证记录”。
- 当前模型验证失败时显示红色“模型回复失败”；过期验证不作为当前模型的结论。工具连接与模型真实回复分别表达。
- 模型不可用优先提示检查模型并重新验证，包括已存在原生 Session 的记录。旧失败结果、原始 ID、未知任务占用保护均保留。
- 已为日常 WSL 实例 opencode-a5193e 设置 csi-provider/DeepSeek-V4.1-Flash，并完成真实回复验证。只修改 AgentBridge 实例覆盖；OpenCode 全局配置、凭据及 Windows Claude 实例模型未修改。这不是面向所有新安装的默认模型策略。

## 使用与恢复

打开 0.4.4，点击“新建任务”，选择 WSL Ubuntu 的 OpenCode 项目实例，输入实际需求。旧失败记录仍可从诊断开关查看，其失败结果不会被改写成成功。

模型覆盖可在该实例“模型设置”中改为其他已有可用模型，或恢复继承；后者会重新受全局模型配置影响。配置改变后应新建会话，旧会话不能静默切换模型续问。需要重新验证时显式触发一次，不自动重放旧失败请求。

便携版及 SHA-256 校验结果见 [打包记录](../../../artifacts/I04D-build.json)。仓库产物为 desktop/release/AgentBridge-0.4.4-Windows-x64.exe。
