# I04F：流式回答与连接验证展示

日期：2026-10-10。桌面版本：0.4.6。

用户在连接验证详情中看到 AB、_VERIFY、_e 等零碎输出。Claude 原生接口返回增量文本，后台逐条保存是正常行为；界面将每个片段分别渲染为输出事件，又将隐藏的原生元数据事件计入数量，导致一个短回复显示大量执行步骤。这不表示重复调用模型。

已只读核对用户这条原验证：任务成功，完整回复与要求的标记一致。159 条原始事件包含 140 条 native 元数据、16 条 output 片段，以及接收、开始、完成各 1 条。新版验证过程对应 3 个可见步骤，见 [原记录核对](../../../artifacts/I04F-existing-verification.json)；核对没有新增模型调用。

## 交付行为

- 普通回答在同一文本区域显示已收到的回复，任务结束后以完整终态回答为准。
- Claude 相邻输出片段按增量拼接；OpenCode 相邻前缀快照替换旧快照，避免重复文字。工具和状态事件保持顺序，不跨工具活动合并。
- 执行过程数量只统计可见步骤。完成步骤显示完成状态，避免再重复展示整份回答。
- 验证详情标题显示“连接验证”，回答页显示“验证结果”。成功时显示“模型真实回复验证通过”，进行中保持验证提示，不把标记分片逐条展示。
- 原始验证请求和完整回复可在“诊断信息”展开查看。原始事件、序号、任务 ID、模型调用和对账逻辑不修改。
