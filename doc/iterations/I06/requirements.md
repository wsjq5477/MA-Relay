# I06 功能需求与验收基线

日期：2026-10-10。状态：计划，全部 I06 功能待开发、待验收。上一迭代实际能力见 [I05 验收](../I05/acceptance.md)。迭代目标与增量见 [proposal.md](proposal.md)，技术合约见 [ssh-design.md](ssh-design.md)、[graph-design.md](graph-design.md)，逐项测试见 [testing.md](testing.md)。

## 1. 用户与对象

本轮面向同一操作者管理 Windows、本机 WSL 与已授权 Linux SSH 账户。操作者具有安装用户态 Bridge 后台的权限；Agent 在其所在机器沿用原生登录和权限。不是多租户团队平台，不赋予主 Agent 安装工具、修改账户或创建 SSH 连接的管理权限。

| 对象 | 含义 |
| --- | --- |
| Coordinator | Windows 上独立常驻的中央路由与协作权限后台；没有模型配置 |
| Machine | 一个稳定执行环境，展示系统、登录执行域、连接状态和工具；Windows / WSL 保留宿主关联 |
| SSH Connection | 地址、端口、用户、可信主机密钥、认证引用和连接策略；不保存明文密码到配置 |
| Daemon | Linux 登录用户下的独立后台，持有工具扫描、任务执行与原生会话台账 |
| AgentNode | 机器上的实际工具接入节点，不绑定项目、模型、供应商；版本升级不改变身份 |
| Collaboration | 一个用户指定的主节点与允许子节点的定向关系，后台权威保存修订号 |
| GraphLayout | 节点/机器分组位置及画布视口；与授权关系分开保存，不改变执行权限 |
| Task / Conversation | 具体执行意图、目录、父子关系、原请求 ID、原生 Session 与结果 |

远端机器身份表示 Bridge 执行环境，不等于认证硬件序列号。同一 Linux 服务器的不同 SSH 用户不能共用任务、原生账户或目录锁；同一后台的地址别名不能绕过去重与占位。

| ID | 功能与正常行为 | 异常与边界 | 可验收结果 |
| --- | --- | --- | --- |
| I06-SSH-01 | 添加 Linux：IP/域名、用户名；端口默认 22；密码、私钥或本机 ssh-agent；按钮“检测并连接” | 拒绝非法地址/端口/用户和参数注入；无新增机器接入码；基础模式不承诺解析完整 OpenSSH config/ProxyJump | 三种认证方式有对应证据；错误密码、地址、端口分别给可读原因；不创建原生 Prompt |
| I06-SSH-02 | 认证前校验服务器主机密钥；首次显示地址、算法、SHA-256 指纹供确认；已信任自动核对 | 已记录指纹变化阻止连接，不自动接受；用户拒绝不提交密码、不安装后台 | 首次接受/拒绝、已知匹配、变化拒绝四分支通过；关闭校验的产品选项 = 0 |
| I06-SSH-03 | 密码/私钥口令隐藏输入；可选记住密码，Windows 系统凭据保护；私钥只由可信后台读取；配置只存引用 | 不记住则当前连接可用，需新认证时提示输入；密钥失效/系统凭据不可用有修复入口；不转为明文保存 | 快照、日志、进程参数、安装命令、错误和验收产物中泄露数 = 0；记住与不记住行为准确 |
| I06-SSH-04 | SSH 内建立双向 daemon RPC，握手版本/来源/连接代次，完整解码和有界消息 | 超大/非法帧、版本冲突、旧连接回应、远端 stderr 不得污染协议；用户数据不拼接可执行 Shell | 正常请求/回调、拆包粘包和 UTF-8 有测试；非法/旧代次拒绝；SSH 断开只影响目标来源 |

选择密钥文件是可访问按钮/文件选择器，登录方式用选项卡或单选卡，不做模型/供应商下拉向导。SSH 主机身份确认不是每次接入重复执行的步骤。

## 3. 远端 daemon 需求

| ID | 功能与正常行为 | 异常与边界 | 可验收结果 |
| --- | --- | --- | --- |
| I06-DMN-01 | 检测系统/架构、当前用户、家目录、可用磁盘/目录、Node ≥22.13、已安装受支持 Agent 与版本 | 支持基线 Linux x64；缺依赖/不支持架构明确说明；安装检查不调用模型，不读取回显原生密钥 | 空工具机器仍显示；未满足依赖不谎称已连接；报告记录真实 OS/运行时/工具版本 |
| I06-DMN-02 | 展示 Bridge 用户态安装摘要，用户点击安装并连接；部署已校验版本包，创建私有目录，启动或复用 daemon；无兼容 Node 时部署 Bridge 私有运行时 | 不用 sudo，不改系统 Node/原生登录配置，不覆盖非 Bridge 文件；传输/校验/磁盘失败可恢复；无目标平台运行时包则明确阻塞 | 全新安装/已有后台复用/缺 Node 私有运行时分支通过；Bridge 未修改原生配置；损坏包拒绝执行 |
| I06-DMN-03 | daemon 与 SSH relay 分离，拥有目录锁及可校验进程/IPC 身份；关闭窗口、断开连接后已接收任务继续 | 防止两个后台抢同一目录；PID 存在不足以证明归属；断开不等于取消；显式停止/卸载不能杀非所属进程 | 窗口退出/SSH 中断无 task 自动取消或重跑；重复启动一个后台；停止只操作自己的资源 |
| I06-DMN-04 | 持久用户作用域 daemon ID，握手返回实际用户/环境/协议/能力；关联 SSH 可信来源建立稳定机器和工具节点 | 主机/用户/daemon 身份不一致先阻止绑定；同服务器不同用户隔离；同后台地址别名复用原身份 | 重连/重启/工具升级重复机器/节点 = 0；来源伪造拒绝；用户执行域不串用 |
| I06-DMN-05 | 显示版本兼容性；升级暂存、校验、原子切换、健康验证和失败回滚；保留原状态与会话 | 在途/等待/unknown 任务阻止自动版本切换；不自动升级 Node/Agent；卸载保留历史为默认 | 忙时不杀任务；损坏/不兼容版本不覆盖可用版本；失败能回到上个兼容版本且历史一致 |

首次用户态安装属于本轮接入动作；系统开机启动、自动 sudo 注册 systemd 或系统服务不属于基础接入。服务器重启后，Windows 重连可启动已安装 daemon；Bridge 不假设用户登录 shell 的 PATH 与非交互 SSH 一致。

## 4. 中央协调与跨设备协作

| ID | 功能与正常行为 | 异常与边界 | 可验收结果 |
| --- | --- | --- | --- |
| I06-NET-01 | 桌面自动启动/复用独立 Windows Coordinator，通过本用户保护的本机 IPC 调用；后台持有机器连接与协作回调 | 关闭窗口不退出 Coordinator；退出整个后台另设明确动作；Windows 关机/休眠会失去协调，不宣称高可用 | 无第二终端；窗口关闭期间后台仍能查询及处理真实协作；重复 EXE 启动不创建第二协调者 |
| I06-NET-02 | 统一 Windows / WSL / Linux 目录；机器下工具节点；所有任务路由以来源机器和稳定节点为准 | 远端目录不按 Windows/WSL 规则转换；模型/账户/供应商原生继承；不自动同步文件；离线保留记录 | 多工具按实际扫描；旧任务/会话不串来源；远端目录验证与真实使用通过；无模型覆盖参数 |
| I06-NET-03 | 任意已接入节点可为主；MCP 列表、委派、结果、取消、等待项沿机器通道路由；父子任务与主 Session 关联 | 列表/新委派校验当前主与保存关系；换主/清主/撤销阻止旧主新委派，但其存活原父 scope 可按既有归属查/控旧子；新主不接管旧子 | Windows 主到 Linux 子、Linux 主到 Windows 子各一条完整真实链；越权、伪造及新主接管旧子成功数 = 0 |

Server 是 Coordinator 的产品称谓；本轮不增加需要远端连入的 HTTP/WSS Server，不复制 I01 的演示 Token 给远端服务器。旧 Hub/Edge 与 CLI 继续兼容使用，不能另建一份冲突的任务数据库。

原父任务结束后，其原生 MCP 作用域失效；人工仍可通过桌面按原任务归属核对或处理尚未结束的子任务。不能将“当前主节点”检查统一应用于所有旧任务查询，也不能因为旧任务需要核对而继续授予旧主新的委派能力。

## 6. 持久化、恢复与任务控制

| ID | 功能与正常行为 | 异常与边界 | 可验收结果 |
| --- | --- | --- | --- |
| I06-REC-01 | 中央持久执行意图，daemon 原生调用前持久去重收据；稳定 ID 与内容摘要；unknown 保留节点/目录占位 | 网络超时/回执丢失只查询原请求，不能创建新 ID 旁路；同 ID 不同内容冲突；不能靠删除连接解除占位 | 同 ID 并发 10 次执行 = 1；调用边界故障点重放 = 0；有/无收据均有清楚状态 |
| I06-REC-02 | 取消/权限/表单使用原 task/execution/request/operation ID；来源与父会话归属校验；回执和实际效果分开 | 丢回复查询原操作，不补发；不支持原生能力明确返回；自然完成与取消竞态保持可信终态 | 丢取消/回复回执不重复动作；确认取消须有原生证据；跨会话控制拒绝 |
| I06-REC-03 | 断网、SSH 中断、Coordinator/daemon 重启、窗口重开按原 ID 和原生 Session 对账，保留事件和终态 | 无法查证不解除占位；单边离线不全局阻塞；中央停止期间协作调用可能失败，保留事实不假装成功 | 原 Task/Conversation/nativeSession 关联一致，历史丢失 = 0，自动 Prompt 重放 = 0；受控恢复满足计划时限 |

恢复不是执行重试授权。I06 不提供离线排队、未知任务一键清零、会话跨机器迁移或把失败续聊改成新会话的降级。主动重做必须由用户创建新需求，并保留原失败/unknown 事实；有未知占位时先解决原执行。

## 2026-10-12：自然语言发现回归需求

I06-FIX-CX-01（关联 I06-NET-03、AB-F13、M06-CX-F01、M08-F02/F05）：用户仅询问主 Agent 的模型和已连接子 Agent 时，Codex 应通过 AgentBridge MCP 发现已允许节点、实际询问子节点并读取结果汇总连接图。不得使用 Codex 内部临时 Agent 列表证明 Bridge 无连接；MCP 缺失/失败明确报通道故障。新会话与原 thread 续聊均收到协作指引，普通任务不改输入，原始消息、requestId 去重、原生配置与许可范围保持。仅自报或可确认依据可标为模型信息，精确标识未知不猜测。

## 2026-10-12：已安装后台兼容复用需求

I06-FIX-SSH-01（I06-NET-02、AB-F05/06/11、M04-F04/F06、M05-F01/F02）：新客户端补丁版不得仅因 app 版本不同而阻断已验证兼容的原 SSH daemon。复用必须以本地可信发布清单和原 profile/owner/UID/daemonId 为依据，校验原版本内容与路径；未知发布、被篡改清单、目录别名和身份不符拒绝。保留原进程、任务、历史、unknown 占位；无自动升级/安装/模型任务。


## 2026-10-12：重连后旧机器报错清理需求

I06-FIX-SSH-02（AB-F01/05/11/17）：成功重连后同一机器的旧版本/连接错误撤销并持久化；重开不恢复旧提示。当前连接拒绝与 RPC 失败继续展示，不能按在线状态隐藏全部错误，不改机器/节点身份或任务失败/unknown。实现与验收见 [alpha.5 交付](ssh-error-recovery.md)。
