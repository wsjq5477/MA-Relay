## 1. 交付目标与现状差距

用户打开 AgentBridge 即可看到本机 Windows、属于它的 WSL 环境以及接入的 Linux 服务器，每个机器分组内显示实际发现的 Agent 工具节点。用户在节点上设定主 Agent，再从主节点输出端点拖到子节点输入端点，保存后形成后台真正执行的定向授权。主、子可以处于任意已接入机器，不按操作系统或 machineId 限制连接。

图上的连线表示“允许这个主 Agent 委派任务给这个子 Agent”。机器在线、SSH 已连接、daemon 正常、工具能启动和模型真实回复是不同事实，分别展示。画出连线不能将离线机器标为在线，也不能把工具发现成功当作真实调用成功。

| 当前 0.5.0 | I06 变化 |
| --- | --- |
| 机器筛选使用下拉框 | 可点击的机器标签与画布定位，默认显示全部机器 |
| 主 Agent 下拉选择、子 Agent 复选框 | 节点动作“设为主 Agent”、输出端点到输入端点拖拽连线 |
| 保存后只读文字拓扑 | 可编辑的机器分组节点图，实际关系、草稿、状态同时可见 |
| 新建会话的执行目标下拉框 | 点击图中节点或机器分组中的节点卡选择目标 |
| 没有布局、缩放与平移 | 节点/机器组拖动、平移、缩放、适配视图、自动整理、布局恢复 |
| 关系 revision 更新会覆盖本地编辑 | 关系草稿独立管理，轮询只更新运行状态，冲突显式处理 |
| Windows / WSL 本机进程通信 | 增加真实 SSH Linux 机器卡、接入进度与重连状态 |

任务/会话所属目录仍在具体执行时填写。图中不出现模型、供应商、默认项目目录配置。已有安装位置只在节点详情中按需展开。

## 3. 页面信息结构

### 3.1 机器与 Agent 页面

页面上方显示“机器与 Agent”、机器/执行环境数量、“添加 Linux 服务器”“重新扫描”。下面为机器标签与机器分组节点画布；默认显示全部机器，不要求先配置项目。

机器标签只控制视图，不修改已保存关系、不自动换当前主 Agent。点击标签可聚焦该机器；“全部机器”恢复全图。任务看板和会话页的机器过滤采用同样的标签，避免下拉框。

机器分组头部显示：名称、系统/连接方式、连接状态、最近成功同步时间、发现节点数。机器操作为“重新扫描”“连接详情”“重新连接”；远端机器另有“断开”“移除连接”。断开与移除的实际后台行为由接入模块执行，不能只隐藏卡片。

| 分组 | 必须显示的信息 |
| --- | --- |
| Windows 本机 | 本机标识、Windows、后台连接状态 |
| WSL 环境 | `WSL · Ubuntu` 等发行版、宿主 Windows 名称；明确与宿主是同一物理电脑的执行环境 |
| SSH Linux | 远端名称、Linux、`SSH · 用户名@地址:端口`、daemon 连接状态 |

WSL 分组与 Windows 分组视觉相邻，并以宿主标签关联；不把 Windows→WSL 的成功链路作为两台物理电脑的验收证据。远端 Linux 可以是实体服务器或虚拟机，界面不推测其物理属性。

### 3.2 协作关系页面

复用同一机器分组和节点组件，默认完整展示网络。工具栏显示主 Agent 名称、已保存成员数、草稿状态、保存/放弃更改、自动整理、适配视图和缩放控制。未设置主节点时提供一句引导：“点击一个已接入节点，设为主 Agent，再拖动端点连接子 Agent。”

选中节点后在侧面详情区显示机器、工具、版本、状态、安装位置及可用动作；详情区不遮盖当前连线。选中边后显示“允许委派：主节点 → 子节点”和“删除这条授权”。删除为草稿变化，保存后生效。

最近委派记录保留机器/节点/父子任务与真实状态，可展开进入任务详情。连线附近可以显示该关系当前活动任务数量，不能把任务进度当作连线权限本身。

### 3.3 会话目标选择

从节点点击“开始会话”时，目标固定为该节点，表单顶部显示可点击的目标卡。新建普通会话可打开紧凑的节点选择面板，按机器分组点击节点，不能使用下拉框。

从“向主 Agent 发需求”进入时，目标为已保存的主节点，并启用协作。未保存草稿不能成为执行目标或协作授权。用户点击普通子节点会话时，保持普通执行，不自动启用主任务身份。

可选执行目录放在表单的“执行目录”展开区，明确目录属于目标机器。切换目标后清空尚未提交的目录，需求文本保留；不将 Windows 路径静默转换为远端 Linux 路径。已存在会话续问锁定原机器、节点和目录。

主题设置与本需求无关；现有主题控制可保留。机器、主从和会话目标这三个核心流程必须移除下拉选择。

## 4. 节点、端点与边

### 4.1 节点内容

每个 AgentNode 卡显示工具名称/图标、版本、所属机器、主/子角色标签、接入和运行状态。稳定 nodeId 用于数据关联，在界面上按需查看，不作为主要标题。

只有确实扫描到的工具创建节点。曾登记的工具缺失或机器离线时保留节点及历史，显示最后已知状态。未安装过的工具不能画成在线或可调用的预置节点。无支持工具的机器仍有空分组，提供“未发现受支持的 Agent”和重新扫描动作。

已发现但未接入的节点有一个“接入”动作，或沿用空格多选一次接入。接入不询问项目、模型、供应商，不因接入自动发送验证 Prompt。主从图使用节点动作与端点完成配置，不能退回旧的子节点复选框表单替代图。

### 4.2 唯一主节点

选中已接入且具有执行适配的节点，点击“设为主 Agent”。离线的已接入节点可以配置为主节点，但不能执行任务；未接入、尚未适配节点不能新增为主节点。

切换主节点时，旧主节点和所有旧授权仍属于已保存版本；本地草稿设置新主节点并清空草稿成员。界面立即显示“主 Agent 已更改，旧的 X 条授权将在保存后移除，请重新连线”。不能把旧边静默改向新主节点，也不弹出逐项确认。

清除主节点同时清空草稿成员。已经运行的主任务及子任务不会随配置变化迁移或自动重发。保存换主/清主/撤销后旧主不能新委派，但其仍存活的原父任务作用域可按原归属读取、取消或处理已委派子任务；新主不能接管旧子。父任务结束后其原生 MCP 作用域失效，人工仍可在桌面按原归属核对未结束子任务。

### 4.3 拖拽连线

主节点右侧显示“允许委派”输出端点；其他已接入且支持执行的节点左侧显示“接收委派”输入端点。主节点输入端点不作为有效目标，普通节点输出端点不允许首版递归委派。

操作为：按下主输出端点 → 临时连线跟随指针 → 可接收目标高亮 → 在输入端点释放 → 增加草稿边。跨机器与同机器使用完全相同的操作。释放在空白、按 Escape 或窗口失去焦点时取消临时线，不新增节点和权限。

| 连接情况 | 反馈及结果 |
| --- | --- |
| 当前主节点 → 已接入的其他节点 | 增加一个草稿成员，允许跨机器 |
| 相同边再次连接 | 显示“已存在这条授权”，不新增重复记录 |
| 自身、子→子、子→主、输入→输入 | 临时线标示无效并说明原因，数据不变 |
| 尚未设置主节点 | 提示先设主，不把第一次拖动的节点自动设为主 |
| 未接入或未支持执行节点 | 提示先接入/尚未支持，数据不变 |
| 已接入节点当前离线或忙 | 可以配置授权；显示运行限制，执行仍由后台拒绝或等待核对 |
| 目标在编辑过程中被明确移除 | 保留错误提示，禁止保存失效引用，要求重新选择 |

边使用箭头表达主→子方向。已保存授权为实线；新增草稿边为虚线，并显示“待保存”；删除草稿以待移除标记或撤销入口呈现。离线目标的已保存边变为灰色并附状态说明，不自动删除。不能只靠颜色区分状态。

点击边或按 Tab 聚焦边后，Delete/Backspace 删除该授权草稿；不删除节点、机器或已有任务。删除后可撤销当前草稿变化。新增/删除边只有保存成功后才改变后台 allowlist。

## 5. 画布和布局

节点拖动限制在所属机器分组内。拖动节点不能改变 machineId；跨机器移动工具不是本次功能。拖动分组标题可移动整台机器的分组以及其子节点；宿主关联不随位置变化。

拖动空白背景平移，鼠标滚轮缩放，以光标为锚点；缩放范围拟定为 25%–200%。工具栏提供放大、缩小、100%、适配全部节点、定位主节点。端点拥有至少 24×24 CSS 像素的有效命中区域，节点动作与端点拖动分离，点击按钮不能误拖整卡。

自动整理按机器分组排列，组内按主节点优先、工具名称排序；尽量让主节点所在机器位于视图左侧。首次打开和新增机器可自动放入空白区域；轮询、版本变化、状态变化不重新排列。用户手动布局只在主动“自动整理”或“恢复默认布局”时改变。

布局自动保存采用拖动/缩放结束后短暂合并写入，写入失败显示“布局尚未保存”，保留当前画面和重试入口。布局错误不能修改或撤销授权。授权有草稿时，自动整理只修改布局。

建议独立持久化 `graph-layout.json`，由中央后台提供布局读写接口，桌面不直接写远端机器文件：

```ts
interface GraphLayout {
  version: 1;
  layoutRevision: number;
  groups: Record<string, {x: number; y: number}>; // machineId
  nodes: Record<string, {x: number; y: number}>;  // nodeId，分组内坐标
  viewport: {x: number; y: number; zoom: number};
}
```

布局不保存 role、members、在线状态、凭据、目录、模型或供应商。布局写入请求另带稳定 `operationId` 和 `expectedLayoutRevision`；后台原子保存新布局、修订与操作收据，同 ID 相同内容返回原结果，回应丢失时先查询原操作。有限坐标、缩放范围、条目上限和已知 ID 在后台校验；多窗口采用独立 layoutRevision 防止静默覆盖。布局保存操作只影响视图，不能变更关系 revision。缺少或损坏布局时用默认位置恢复，并保留可排查记录；关系文件和历史不受影响。

## 6. 键盘与可访问性

Tab 可到达工具栏、机器组、节点、端点和边。节点朗读名称包含机器、工具、角色和状态；端点朗读“从 Windows / Claude 允许委派”或“连接到 Linux / OpenCode”。所有状态以文字和图形提供，焦点有清晰轮廓。

端点上的 Enter/Space 开始键盘连线，进入目标导航模式；方向键循环有效目标端点，Enter/Space 完成草稿连线，Escape 取消。目标切换通过 live region 提示机器和工具。此操作使用同一连线校验，不能绕过跨机器授权。

选中节点后方向键以小步移动位置，Shift+方向键大步移动；机器组同样可移动。平移/缩放按钮、自动整理和适配操作均可键盘触发。键盘连线与拖拽连线都要单独验收，不能只依赖图形库的默认可访问性声明。

## 7. 状态分层与 SSH 接入

### 7.1 状态的来源

| 层次 | 界面状态 | 动作 |
| --- | --- | --- |
| SSH / 机器通道 | 未连接、连接中、需核对指纹、认证失败、准备后台、在线、正在重连、离线 | 连接详情、重新连接、断开 |
| 远端 daemon | 未准备、准备中、版本不兼容、健康、异常 | 查看检查结果与明确修复指引 |
| Agent 工具接入 | 已发现、待接入、已接入、工具缺失/检查异常、尚未适配 | 接入、重新扫描、查看原生错误 |
| Agent 执行 | 空闲、正在工作、等待用户输入、执行待核对、最近执行失败 | 查看任务、回复原权限/表单、核对原请求 |
| 协作授权 | 未连接、已保存授权、草稿待保存、保存中、冲突/回应待核对 | 保存、放弃、查询原操作 |

SSH 在线但 daemon 异常时，机器显示“SSH 已连接，后台异常”，Agent 不标为可执行。daemon 在线但原生 Agent 登录、账户、模型失败时，只显示该节点/任务的真实错误，机器保持在线，不推出模型和供应商选择表单。

丢失连接不能直接把运行任务标为失败或取消。尚未确定的任务显示“执行待核对”，保留原 requestId、taskId、机器和节点；恢复时查询原请求。未知操作只阻塞所属机器的相关执行入口，其他机器仍可提交；旧记录没有来源机器时才使用兼容保护规则。

### 7.2 添加 Linux 服务器

点击“添加 Linux 服务器”打开紧凑表单，字段仅包含连接所需信息：

| 字段 | 行为 |
| --- | --- |
| 服务器地址 | IP 或域名必填，不能要求两者都填写 |
| 用户名 | 必填 |
| SSH 端口 | 默认 22，放在可展开的连接选项中 |
| 登录方式 | 分段按钮选择密码、密钥、ssh-agent；展示当前方式必要字段，不用下拉框 |
| 密码 / 密钥 | 密码隐藏显示；密钥选择文件，必要时填写口令；ssh-agent 方式显示可用/不可用 |
| 保存登录凭据 | 按凭据模块规则明确选项；不保存时重连需要用户补充凭据 |
| 显示名称 | 自动读取远端名称，用户可修改，不阻塞初次连接 |

不新增 AgentBridge 接入码、设备 Token 或另一套账户配置。页面不展示密码、私钥内容或把它们拼成可复制命令；错误、日志、诊断、快照与布局均不得含凭据。连接完成后清空表单中的密码/口令副本。

点击“检测并连接”后显示阶段进度：核对服务器 → SSH 登录 → 检查环境 → 准备 daemon → 扫描 Agent → 已接入。已有兼容 daemon 自动复用；首次安装仅展示用户态安装位置、版本和依赖检查摘要，用户点击一次“安装并连接”后自动完成。安装/启动后台使用登录用户目录；缺少必要依赖或权限时给具体错误，不要求用户确认每项内部参数。安装和生命周期的详细规则由 SSH/daemon 设计定义。

首次未知 host key 仅展示主机、端口、算法和 SHA-256 指纹，要求确认可信服务器身份；已有可信记录时直接核对。host key 变化必须中止连接，提供独立重新核对动作，不能自动接受。认证失败提示检查用户名及登录方式；端口不可达提示地址/端口或网络问题；不能统一写“机器不可用”。

连接进度可取消观察；若远端准备操作已开始，界面说明正在核对其结果，不假装撤销已安装文件。连接/安装重复点击被合并到原操作，不能启动两份 daemon。机器稳定 ID 来自接入协议，不能用用户可修改的名称作为身份，也不因 IP 变化重复注册节点。

### 7.3 空图与异常

- 没有远端机器：本机节点仍可见，提供添加 Linux 入口，不做强制向导。
- 机器上没有工具：保留机器分组，说明扫描完成但没有发现受支持工具，不自动安装或登录模型工具。
- 原生账号错误：显示人类可读错误摘要、所属机器/工具和日志入口；修复应在该机器的原生 CLI 完成。
- 中央后台不可达：显示连接异常，保留最后已知图并标示数据时间，停止执行/授权提交；不误标所有远端账户失效。
- 远端离线：保留节点、关系、历史和布局，显式重新连接；不删除边，不偷偷把任务路由到同名本机工具。

## 8. 关系草稿、保存和迁移

后台仍保存 I05 的真实授权模型：

```ts
interface Collaboration {
  leaderId: string | null;
  memberIds: string[];
  revision: number;
}
```

图的边是该对象的投影：每个 member 产生一条 `leaderId → memberId`。不得另存一份可与 allowlist 分叉的“图权限”。成员顺序不具有权限含义，节点 ID 和原始来源机器保持稳定。

前端分别保存 `baseRelation`（已确认版本）、`draftRelation`（本地编辑）、`remoteRevision` 和保存操作状态。运行快照更新节点状态，不重建草稿；正在拖拽的节点位置不被轮询改回。

| 事件 | 行为 |
| --- | --- |
| 无本地编辑，远端 revision 更新 | 接受新关系，保留布局 |
| 有本地编辑，远端 revision 更新 | 保留草稿并标示冲突；显示当前已保存关系与草稿差异 |
| 用户放弃草稿 | 载入最新后台关系，不改布局 |
| 用户保留草稿继续编辑 | 以最新版本重新校验节点，展示新增/移除的差异；用户再次保存后才写入 |
| 保存明确成功 | 更新 base/draft/revision，边变为已保存；提示已生效 |
| 保存明确拒绝 | 保留草稿，显示具体原因 |
| 保存回应未知 | 显示“正在核对原保存操作”，查询原收据；不得直接生成新 ID 再写 |

保存请求携带稳定 `operationId`、`expectedRevision` 和完整主/成员集合；后台原子检查 revision、所有节点是否存在/已接入、唯一主与无重复/自连接，再保存授权及操作收据。同 operationId 相同内容返回原收据，不同内容拒绝。该原操作查询能力应纳入中央接口与 journal，而不是靠 UI 的“成功提示”推测结果。

点击保存只是提交真实授权，没有额外确认弹窗。保存过程中可查看节点状态，但暂停新的权限编辑；保存成功与否以后台收据为准。后台即使收到绕过图的请求，也必须再次拒绝自身、伪造来源、未允许目标、失效主任务作用域和递归扩大权限。

启动 0.5.0 配置时，沿用原 leaderId/memberIds/revision 并生成默认布局，不重新生成节点 ID，不修改 machines.json、原生会话、历史任务与请求收据。布局迁移有单独版本标记；重复启动不再迁移。旧失联节点以历史节点显示，不静默删除授权。损坏的关系文件必须明确报错和保留原文件，不能用空图覆盖。

## 9. 前端实现边界与技术选型

I06B 已锁定 `@xyflow/react 12.12.0` 和 lockfile，实际兼容、交互与离线包结果见实施报告。该库提供图组件、端点和可访问性入口，业务身份/权限/SSH凭据仍由项目模块管理。参考官方 [组件接口](https://reactflow.dev/api-reference/react-flow)、[端点](https://reactflow.dev/learn/customization/handles)、[可访问性](https://reactflow.dev/learn/advanced-use/accessibility)。

技术选择的进入门槛：隔离机器组、端点鼠标连接、组内节点拖动、整体平移缩放、中文键盘朗读、深浅主题、打包后离线加载均通过；不依赖在线 CDN。未通过时先修复兼容或记录替代方案，不以只读 SVG 图冒充可编辑交付。

建议拆分：

| 文件/模块 | 职责 |
| --- | --- |
| `NetworkApp.tsx` | 页面组合、已确认快照、会话目标与图入口；移除旧关系表单 |
| `AgentGraph.tsx` | 机器组、节点/边呈现、端点/键盘交互、画布工具栏 |
| `graph-state.ts` | 图数据投影、草稿/差异、非法连接校验、修订冲突与布局映射 |
| `AddMachineDialog.tsx` | SSH 表单、host key 确认和接入进度；只通过后台凭据接口提交 |
| `types.ts` / `api.ts` | 机器接入状态、布局和保存操作收据契约 |
| `network.css` / 图样式 | 与现有主题变量一致的卡片、角色、状态、焦点、端点和边 |
| 中央后台 | 权威关系、修订与收据、布局校验、机器连接操作和任务来源隔离 |

图选型不改变一个主节点的协作模型；库生成的任意 source/target 不能直接成为后台权限。机器组的几何 parent 与 WSL 的物理宿主 parentMachineId 也必须分开，不能用绘图父节点覆盖机器归属。

交互性能目标在 Windows 验收机记录硬件、窗口大小和节点规模后测量：20 个机器组 / 60 个工具节点夹具中，选择/端点预览/拖动首个反馈的 p95 ≤ 100 ms；连续拖动期间无超过 500 ms 的主线程卡顿。该数字是待测目标，不能以设计文档代替实测结果。初次入图适配全图，常用窗口下端点与状态文字可辨认；1366×768 与 1440×960、深浅主题分别检查。

自动化须用实际鼠标坐标执行端点按下、移动、释放，并核对后台关系收据；不能直接改组件 state 或调用 saveCollaboration 来替代拖拽验收。覆盖取消拖动、方向错误、重复线、离线边、选中删线、设主旧边不改向、布局重开、键盘连线、draft/revision 冲突与来源机器未知占位。

人工验收以真实第二台 Linux 服务器为前提：从 Windows 添加服务器，看到真实工具，图中连线授权，提交需求，展开原生子任务及主 Agent 汇总；反向选择 Linux 节点为主也要完成。UI 夹具只能证明交互与错误展示，不能作为 SSH/跨物理设备真实执行证据。

证据包括交互录屏或关键截图、浏览器端点操作结果、保存收据与关系修订、布局重开前后、真实 SSH/daemon/父子任务关联记录；所有诊断进行凭据脱敏。最终报告分别列 UI、机器接入、真实协作、故障恢复通过与限制，不能因图已画好就宣称网络接入完成。

当前键盘实现保持起始端点焦点，方向键通过高亮与 live region 选择目标，回车完成；也支持 Tab 到目标端点完成。该方案避免轮询/图组件重绘造成焦点跳动，采用同一连接校验，不扩张授权。


alpha.6 的机器组/节点在首次渲染即提供明确宽高，parent extent 不等待 DOM 测量再纠正位置；组移动保存组坐标，节点保存组内相对坐标。10 组 Windows 真实交互验收覆盖节点与机器组鼠标拖动、键盘组移动、缩放、重开及原子授权存储，见 [实施报告](graph-implementation.md)。
