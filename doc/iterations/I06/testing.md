## 1. 验收范围与基线

I06 要交付 Windows 独立中央后台、通过 SSH 接入另一台物理 Linux 服务器、用户态常驻 daemon、双向主从调用，以及机器分组的可拖拽节点图。SSH 使用服务器已有用户名及密码、密钥或 ssh-agent；用户不配置 AgentBridge 一次性接入码或设备 Token。内部任务身份及 MCP 调用授权仍须验证，不能因为 SSH 登录成功就开放任意 Agent 委派。

基线为 [I05 验收报告](../I05/acceptance.md)。Windows ↔ WSL 属于同一宿主的两个执行环境，只计本机回归，**不能作为跨物理设备验收证据**。界面发现成功、SSH 登录成功、daemon 连接成功、原生 Agent 回复成功分别记录。

I05 已知限制保留：Windows Codex 原模型被账号拒绝；WSL Codex 原生续聊返回 `list_turns is not supported yet`。I06 不改模型、登录方式或原生状态数据库来绕过限制，不新建会话冒充原会话恢复。测试环境的原生工具版本与能力另外记录，不能将旧限制泛化到所有 Linux Codex。

## 2. 验收前置条件

正式跨设备验收需要准备以下资源，现在只列条件，不假设用户已提供：

| 资源 | 条件与记录 |
| --- | --- |
| Windows 机器 | 可运行最终 EXE；有隔离 Bridge profile；Claude 已以该用户原生方式登录并能回复。 |
| 独立 Linux 服务器 | 与 Windows 属于不同物理设备；提供授权使用的 IP/域名、SSH 端口、用户和认证方式；记录发行版、架构与 SSH 服务版本。 |
| Linux 用户 | 非 root 用户即可；其用户目录可写，有运行 daemon 及原生 Agent 的权限。无 sudo 的接入路径必须验证。 |
| 远端原生 Agent | 至少 OpenCode 已由该 SSH 用户安装并登录，原生 CLI 先完成一次只读随机标记回复。账号或模型不可用属于环境阻塞，不自动配置替代模型。 |
| SSH 场景 | 密码、文件密钥、ssh-agent 分别准备测试账号或隔离 SSH 配置；另备无凭据保存的重连场景及可控主机密钥变更夹具。 |
| 文件任务 | Linux 用户目录下创建独立验收示例，备份初始内容；仅修改这一示例，不使用用户真实项目。 |
| 故障控制 | 可断开本次测试 SSH 通道、停止隔离后台或 daemon；不得终止其他用户或日常 Agent 进程。 |
| 配置完整性 | 对测试会读取的原生配置/偏好文件记录哈希与存在性；不输出配置正文、认证内容、私钥或数据库内容。 |

不具备独立物理 Linux 时，合约与 UI 可以完成，但 `REL-02` 必须记 `not_tested` 或 `blocked`，不能宣布远程接入已验收。凭据由安全输入路径提供，不出现在命令参数、测试报告或截图。

## 3. 分层执行与证据边界

| 层级 | 执行方式 | 能证明什么 | 不能替代什么 |
| --- | --- | --- | --- |
| L0 工程回归 | 根测试、桌面测试、lint、类型检查和构建 | 原有合约、迁移与新代码检查 | SSH 或模型真的可用 |
| L1 模块与故障合约 | 假时钟、受控传输、实际隔离子进程、状态文件 | 去重、状态机、授权、故障与生命周期 | 真实服务器认证、原生模型协作 |
| L2 真实 SSH | Windows SSH 客户端连接独立 Linux；远端使用受控执行器 | 指纹、认证、安装、双向通信、断线和远端独立生命周期 | 真实 Agent 推理和原生 Session 续聊 |
| L3 真实 Agent | L2 通道上调用原生 Windows Claude 与 Linux OpenCode | 直接回复、原生续聊、双方委派与真实结果 | 最终 EXE 的打包及正常启动 |
| L4 隔离界面 | 浏览器 Mock 的鼠标、键盘、布局和状态测试 | 图交互、可读状态、草稿冲突 | 真实 SSH 连接或原生执行 |
| L5 最终 Windows EXE | 普通启动隔离 profile，经真实 SSH 完成核心使用流程 | 打包资源、后台常驻、跨机器使用、重开保留历史 | 其他未经测试平台或网络环境 |

L1 中实际 SSH 守护进程夹具可作为确定性协议测试；如果其与 Windows 同宿主，标记为 `ssh_fixture`，不归入独立物理机 L2。每条结果记录自己的层级、执行器及是否调用真实模型，禁止把 Mock 的结果正文包装成原生结果。

现有可执行工程检查如下；它们不会自动覆盖尚未实现的 I06 用例：

```bash
npm run lint
npm run typecheck
npm test
npm test --prefix desktop
npm run desktop:build
```

`npm run desktop:dist` 是现有打包入口。I06 SSH、daemon、图交互和真实 EXE 的专用测试脚本需在开发中新增；本文中的 `T-*` 是测试编号，**不是已经实现的 CLI 命令**。实际报告须写明最终使用的脚本、参数结构及退出码。

## 4. 统一指标与观察窗口

| 指标 | 判定窗口与阈值 |
| --- | --- |
| 状态同步 | 已连接、受控 LAN 下制造 20 次确认落盘的状态变化；从后台确认时间至界面显示时间，p95 ≤ 2 秒。排除 SSH 握手、安装下载和模型计算时间，保留全部样本。 |
| 图交互 | 按图设计的 20 个机器组 / 60 个工具节点夹具，记录 Windows 硬件、窗口和主题，采集至少 20 条选择/端点预览/拖动交互样本。从浏览器真实鼠标/键盘输入事件时间至首个可见反馈，p95 ≤ 100 ms；连续拖动无超过 500 ms 的主线程卡顿。保留输入事件、反馈和卡顿原始时间记录，不直接改组件 state 代替输入；与网络状态同步 p95 ≤ 2 秒分别计时，属于待实测门槛。 |
| 失联判断 | 心跳周期 5 秒；连续 15 秒无有效回应即判离线。L1 使用假时钟检查 15 秒边界，真实测试允许一个界面刷新周期的呈现延迟；历史节点和授权边保留。 |
| 重连与对账 | 在网络、主机身份和认证均恢复且凭据可用的受控 LAN 中，30 秒内重建连接并开始查询原请求。密码未保存时显示等待输入，等待用户的时间不计入 30 秒。 |
| 原请求去重 | 同一来源、同一请求 ID、同一内容并发 10 次，原生创建次数 = 1；同 ID 不同内容拒绝，次数仍 = 1。普通任务、子委派和控制操作分别测试。 |
| 零隐式执行 | 扫描、连接、刷新、重开、重连、布局调整产生的模型调用数 = 0；没有明确提交时不创建原生任务。 |
| 身份稳定 | 同登录用户、同 Bridge profile 的同后台地址别名接入、重启及重复扫描新增机器/节点数 = 0；两个独立测试 profile 不强制合并。机器身份是执行环境标识，不证明硬件身份；原 nodeId、requestId、taskId、原生 Session 归属错配数 = 0。 |
| 配置只读 | Bridge 对原生账号、模型、供应商和偏好文件的直接写入数 = 0；记录配置哈希并核对变化来源。原生工具正常写自己的会话/运行状态单列，不当作 Bridge 改配置；接入时必填项目/模型/供应商/Bridge 接入码数量 = 0。 |
| 安全边界 | 假来源、过期 scope、未授权目标、路径/参数注入均无法执行；密码、私钥内容和认证头泄露数 = 0。 |

首次安装与公网下载记录实际耗时、失败原因和重试行为，不设置不可控的下载 SLA。真实模型回复只设测试观察超时；超时不等于任务失败或允许重发，必须保留原请求并核对。

## 6. 可重复故障注入目录

故障开关只存在测试夹具/隔离代理中，不在正式产品里暴露“跳过认证”“绕过去重”或任意进程终止接口。每次故障使用独立 runId，保存故障前后状态，恢复时只查询原请求。

| 编号 | 注入位置 | 注入方式与必须观察的结果 |
| --- | --- | --- |
| F01 | 本地意图落盘前 | 写入失败/磁盘满；SSH 下行提交数 = 0，节点不被误占用。 |
| F02 | daemon 收到任务并持久化后、ACK 返回前 | 丢该响应并断通道；重新连接只查原请求；执行计数 = 1。 |
| F03 | 原生启动后、任务收据保存后 | 断 SSH，远端继续；终态在恢复后按原 taskId 回传，不能重建 Session。 |
| F04 | 原生已输出、事件尚未到中央 | 暂停上行/打乱两类消息；事件去重有序，不把部分输出当终态；父子结果来源保持正确。 |
| F05 | cancel/reply/form 已被原生接收后 | 丢控制回应；状态 unknown，查原操作恢复；执行/控制接收计数不增加。 |
| F06 | 中央进程 | 只终止隔离中央后台；远端任务继续，重启恢复意图和连接。远端主回调失败可见，不伪造子任务完成。 |
| F07 | daemon 进程 | 只终止已核验归属的隔离 daemon；按原生可核验证据接管或 unknown，不能重跑任务。 |
| F08 | 连接代次 | 旧 SSH 迟到 ACK、旧快照覆盖新快照；必须按代次和请求归属拒绝过期消息。 |
| F09 | 安装切换 | 上传半包、摘要不符、原子切换失败；保持旧版本可启动，不覆盖状态。 |
| F10 | 关系与布局并发 | 草稿未保存时轮询、两窗口同 revision 保存；冲突可见；布局不改授权，离线边不删除。 |
| F11 | 身份/权限 | 不同 SSH 用户与伪造调用参数读取他人任务；拒绝且不泄露结果、路径或凭据。 |
| F12 | 原生证据缺失 | 删除隔离夹具中原生 Session 引用/收据；保持 unknown，不能“未找到→重试执行”。 |
| F13 | 授权保存 | 丢原子提交后的保存回应；同 operationId 并发及不同 payload；revision 检查和提交前后终止后台。原关系/收据同时提交或同时不提交；未知只查原收据，授权修订仅一次，草稿不丢失。 |
| F14 | 布局保存 | 独立 layoutRevision/operationId 的同 ID 冲突、提交/ACK 丢失；只读恢复原收据，布局不回退或冒充已保存，不改变权限修订和连线。 |

L1 故障必须可重复通过；F02、F03、F05、F06 另在真实 SSH L2 重复。F13/F14 用真实中央存储合约与隔离 UI 重复，不能仅 Mock 返回成功；无需模型调用。取消、权限和表单的真实原生能力依适配器记录，不因夹具支持就宣称所有工具支持。

## 7. 人工验收主流程

使用最终 Windows EXE、独立 Linux 物理机、隔离 profile 和已登录的原生工具。以下步骤不得用浏览器 Mock 替代。

1. **添加机器**：填写服务器地址、用户名、默认/自定义端口，使用安全认证输入；核对首次指纹。看到预检、安装、daemon 启动、工具发现的进度，无模型、供应商、项目或设备接入码输入。
2. **识别节点**：看到 Windows/WSL/远端 Linux 的正确层级和实际工具。刷新不增加重复机器或节点；无工具的服务器也显示机器与可读原因。
3. **连接节点图**：将 Windows Claude 设为主，从输出端点拖到远端 OpenCode 输入端点并保存。刷新、重开后关系保持；布局移动不改变授权。
4. **真实远端新会话及续聊**：向远端 OpenCode 发送只读随机标记任务，再要求引用上轮随机标记。检查两轮属于同一原生 Session；留空目录可执行，指定远端示例目录时实际在 Linux 目录运行。
5. **Windows 主 → Linux 子**：只给 Claude 一条需求，让其委派 OpenCode 获取随机标记并汇总。检查主实际调用工具、子真实原生结果和主汇总均存在，用户没有复制子结果给主。
6. **Linux 主 → Windows 子**：反向设置主从关系，重复真实委派。检查远端主 MCP 回调经中央到 Windows，并读取真实子结果；这一步是双向架构的必验项。
7. **真实文件功能**：仅在授权的 Linux 隔离示例中请求修改，例如修复一处计算器错误并运行示例测试。若原生需要权限，按原生授权要求仅允许本次；比对文件 diff、测试退出码与结果。原生没有询问时如实记录，不伪造权限卡片。未授权目录不修改。
8. **断线与取消**：在受控慢任务中断开本次 SSH；确认远端仍运行、图上离线而边保留。恢复后对账原 ID。另对可取消任务发取消，等待原生停止证据；丢取消回应的情况由 L2 故障补测。
9. **后台与历史**：关闭桌面窗口期间让任务继续，重开观察同一任务；重启隔离中央后台，确认没有新 Prompt 或新 Session。全后台停止时远端主无法新委派，界面不能记成成功。
10. **撤销授权**：删除主 → 子的线并保存；新委派遭后台拒绝。保留既有任务和历史，不能靠刷新重新授权。
11. **不保存密码**：再次用不保存密码的连接配置重启后台；显示等待认证，输入后恢复原机器，不新增机器、不偷偷把密码落盘。
12. **清理**：只停止/移除本 runId 创建的后台、daemon 和示例；保留失败证据；不改用户原生账号、配置、项目或日常任务。

每个操作记录用户可见结果和后台证据。实际工具账号失败单列；模型超时后继续只读观察，不能为了得到漂亮截图另换 ID 重提。

| `artifacts/I06-ui.json` 与截图 | Mock 或真实窗口必须分别标记；坐标/端点/保存/冲突与键盘行为。 |

每条检查最少包含：`runId`、`requirementId`、`testId`、`level`、`status`、`startedAt`、`endedAt`、`environment`、`steps`、`expected`、`observed`、`evidenceRefs`、`modelInvocation`、`blockReason`。涉及执行时另包含来源 `machineId`/执行域、`nodeId`、`requestId`、`operationId`、`taskId`、父子归属、脱敏的原生 Session 引用、原生执行次数、终态依据及连接代次；关系/布局保存另含原 operationId、内容摘要、前后各自 revision、持久收据与是否发生重写；时间指标保留样本和计时来源。

脱敏规则：服务器地址和用户名使用报告内稳定标签；确需复现的原地址放在仅本地可访问的测试配置，不复制到公开产物。禁止写密码、私钥正文、密钥口令、认证头、系统凭据存储内容、Provider Key、内部 scope Token。原生模型名称可在受限诊断中记录用于证明继承，不在接入流程新增模型选择。日志保留错误类别与请求 ID，清除可能含凭据的命令行或原生正文；使用固定测试标记，不录真实用户需求。

最终 EXE 采用普通启动，不开启调试/CDP/inspect 接口。检查 ASAR、远端运行资源、daemon 包与最终源代码/版本匹配；资源完整不等于真实连接通过，必须与 L5 结果同时报告。

## 9. 结果定义与准出条件

| 状态 | 含义 |
| --- | --- |
| `passed` | 用例已在注明层级实际执行，所有断言和证据齐全。 |
| `failed` | 已执行且实际行为不满足需求；产品缺陷不能标环境阻塞。 |
| `blocked` | 已明确前置条件阻塞，记录原因和影响项，例如原生账号拒绝或测试服务器不可达。 |
| `not_tested` | 尚未执行或没有相应真实环境；不等于通过。 |
| `partial` | 汇总中部分项已通过，仍存在 failed/blocked/not_tested；逐项保留原状态。 |

I06 准出要求：

1. L0 工程回归通过，原 I05 身份、历史、去重和原生配置继承无退化。
2. 本文 SSH、daemon、后台、关系、恢复的 L1 必验项通过；认证泄露、越权执行、重复原生执行、错路由、配置破坏或历史丢失任何一项失败均禁止正式准出。
3. 至少一台独立物理 Linux 通过 L2 的真实 SSH、用户态安装、常驻、身份和故障恢复；不能以 Windows/WSL 或本机容器替代。
4. Windows Claude ↔ 远端 Linux OpenCode 双向真实模型链均通过；远端主回调是必验项。直接回复、原生续聊和授权范围内文件任务分别有证据。
5. L4 图交互与 L5 最终 EXE 使用闭环通过；关闭窗口后后台继续、重开不重复执行、拖端点保存真实授权、离线保留图均有证据。
6. 最终 EXE、Linux daemon 安装包、部署/使用/卸载文档和验收报告齐全，版本及 SHA-256 可核对。

若缺真实服务器或原生账号导致核心双向链未验证，只能提交“开发完成、验收部分完成”的候选版本，不宣称 I06 正式通过。Codex 等非核心工具的原生能力限制允许单列，但不能掩盖本迭代核心 SSH 与协作链失败。
