# 新程序管理已运行后台的操作说明校正

日期：2026-10-12。现有候选：0.6.0-alpha.4。对应 AB-F14、M01-F08、M02-F01/F07。此次纠正使用说明，并增加实际窗口回归；产品代码和发布包未修改，不增加新功能需求，不重跑模型任务。

## 正确操作

不需要保留旧 EXE 或旧窗口。直接打开新 EXE，进入左侧“设置 → 后台运行”，点击“停止后台并退出”并确认。新窗口通过同一份配置目录的认证 IPC，停止当前仍在运行的旧 Coordinator，然后关闭自身。

再次打开新 EXE，才会从新程序资源启动新版本后台。原配置身份、机器、关系与历史保留；停止客户端后台不取消远端已接收的原生任务。不同 profile 或不能通过身份/协议校验的后台不属于该入口控制范围。

当前侧栏版本来自已连接后台的 preferences；新窗口连接旧后台时仍可能显示旧版本。界面代码来自新 EXE，设置页入口仍可用；不能把该版本显示等同于必须找回旧程序。

此前“先在旧程序设置页停止后台”的措辞错误地把旧窗口可访问作为前提，已修正 README、桌面说明、相关交付说明及 M01/M02/M10 的使用描述。

## 验证来源

新增 [真实窗口脚本](../../../desktop/tests/windows-new-client-stop-old.cjs)，在隔离 Windows/WSL profile 中保留实际 alpha.2 后台并关闭旧窗口，再用 alpha.4 的已打包窗口进入设置页停止旧后台，最后重开当前窗口核对版本与持久身份。过程没有提交原生模型需求，未停止用户生产后台。

脚本复用测试 profile 时可从原 alpha.2 冻结资源启动实际 Coordinator；验证的是真实新窗口与真实旧后台的 IPC/按钮路径，不把它说成独立服务器任务迁移验收。

初次自动化在确认退出按钮触发真实窗口关闭时收到 `Target page, context or browser has been closed`，[初次报告](../../../artifacts/new-client-stop/2026-10-12/initial-report.json)保留。后续通过实际进程退出与 IPC endpoint 停止核验按钮结果，再核对重开，而非仅依据点击返回。最终事实见 [报告](../../../artifacts/new-client-stop/2026-10-12/report.json)、[窗口记录](../../../artifacts/new-client-stop/2026-10-12/windows.log)。

原 93/93 自动化和 alpha.4 包资源/普通启动证据仍是上一次交付基线，不被描述为此次重跑。文档变更执行 `node scripts/check-docs.mjs`；身份、数据格式、RPC 和自动升级范围未改变。自动后台版本切换仍未实现，此处是用户明确确认的停止与重开。

最终实测通过：新窗口设置入口可见并实际停止旧后台；确认旧 IPC 已停止；重开后后台版本为 alpha.4、PID 更换且持久配置身份保持，原生请求数为 0。首次重开自动化过早附着 IPC 的 ENOENT 记录保留为 [启动时序记录](../../../artifacts/new-client-stop/2026-10-12/startup-race-report.json)，后续等待新窗口的本次快照后核验通过；未修改产品代码。
