# I03B 需求规格

状态：已完成开发及本轮验收，结果见 [report.md](report.md)。范围以 [proposal.md](proposal.md) 的 B01–B06 为准。

## B01 会话与轮次

用户新建会话时提交第一轮需求，不增加无意义的命名确认。标题取第一轮内容。会话固定用户、Agent、项目资源及配置指纹，首次绑定原生 Session 后不允许更换。每次续问创建独立 Task、Execution、requestId 和 Message；上一轮成功、失败或确认取消后才能续问。一个项目只执行一轮任务。旧单次 run 自动生成会话，历史也可进入会话查看。更换模型、目录或 Agent 后旧会话拒绝续问，提示新建会话。

验收：同 Session 三轮、上下文延续；每轮只显示自己的回答；重复 requestId 返回原轮；退出与重返不增加原生输入。

## B02 显式取消

用户从任务或会话选择取消，先保存操作 ID，再沿现有授权链路发出 interrupt。Ctrl+C 只退出观察。取消的收据分为已确认、未知、拒绝；任务只有对应原生轮次 idle=interrupted 才成为 cancelled。成功与取消竞态保留成功结果。一次执行所有取消 ID 共享一个写入占位，响应丢失不再中断。

验收：真实运行中及权限等待中取消；重复五次、不同 ID 竞争、响应丢失均最多一次原生写；完成轮拒绝新的取消。

## B03 连接与补传

Edge 断链后保留观察和数据库，按 250ms→500ms→1s→2s（上限）重新连接、注册。事件先持久化，后台顺序补传，Hub 持久化后 ACK，Edge 再推进持久游标。重连只重传事件，不重传 Prompt 或控制写入。协议/身份/存储错误明确显示；存储不可写时停止 Edge，禁止虚假 ACK。

验收：断链、Hub 重启、Edge 重建；丢失 ACK 后重复事件仅应用一次；持久事件丢失 0。

## B04 原轮次对账

恢复时以持久 Execution 和 NativeReference 为依据，只读检查原 Session、Message、目录、配置。Message 后至下一条 user 之前的消息构成该轮证据；历史轮不能用 Session 最新 outcome 覆盖。无新 user、原输入存在而尚无 idle 时恢复观察；权限和文本输入保留；idle 支持恢复成功、失败或取消。缺绑定、输入消失、身份/目录不符、新 user 插入未完成轮，保留 unknown 和占位。

验收：运行、等待、成功、失败、中断、缺证据和外部输入干扰分别覆盖；无自动模型调用、无错误释放。

## B05 异常后台

管理的服务以受保护身份文件记录 PID、内核启动时间、boot ID、进程可执行文件、命令/目录和服务地址、凭据文件引用与摘要。复用前核对全部身份和认证接口；只有明确死亡的旧进程允许重启。存活但身份不符或不可读取时拒绝接管/终止。关闭句柄再次核对身份，避免 PID 重用误杀。外部服务不写身份、不停止。I03A 没有身份文件的历史服务不能凭端口猜测归属。

验收：SIGKILL 后复用原 PID；死服务重启后原生消息仍在；错误 PID、身份篡改、外部服务不被接管或停止。

## B06 CLI 与诊断

菜单增加会话列表和续问，任务详情增加取消、只读对账、继续观察。自动化提供 conversations、conversation、continue、cancel、reconcile，支持 JSON、固定退出码和保留 ID。连接重连状态、任务结果、操作收据分别展示。未知任务有具体原因和对账入口，不能永久转圈。

验收：一个 PTY 完成新建→续问→重返→取消→恢复；显示延迟 20 样本 p95≤2s；服务恢复后 10s 内重新注册/启动对账。
