## 1. 本轮交付目标

用户在一个 CLI 中与同一 OpenCode 会话连续沟通，能主动取消当前轮次；CLI、Hub/Edge 连接或后台中断后，能够重新连接、核对真实执行、继续查看已有任务。能确认完成或中断的执行释放占位，无法确认的执行明确说明原因并保留 unknown。

验收主线：**创建会话 → 第一轮分析 → 同会话第二轮修改 → 退出再进入 → 第三轮提交并取消 → 模拟连接中断 → 自动重连与只读对账 → 查看结果或明确的待核对原因。**

继续使用 Linux/WSL、本机 CLI、现有 OpenCode Adapter。已有单次 `run` 路径保留；浏览器/看板、Agent 委派、其他 Adapter、跨设备部署不在本轮。

## 3. 六项交付需求

| B01 连续会话 | 新建、列出、进入已有会话；查看轮次；继续追问 | 一个 Conversation 固定 owner、执行资源、原生 Session 和执行配置快照；每轮独立 Task/Execution/requestId；同会话与同资源串行；先不支持分支或换目标续接 | 至少 3 轮同原生 Session、3 个独立轮次 Task；第二轮使用第一轮上下文；退出重返不新建 Session/Prompt；已完成历史保留 |

| B05 后台异常后的托管进程处理 | 后台崩溃后重新进入，不需手动排查重复服务；查看明确修复步骤 | 持久化受保护的托管身份、启动时间与服务身份，PID/端口可达不足以证明归属；核对存活托管服务后才可复用；重启仅发生在已确认旧进程退出且符合原生持久会话契约时 | SIGKILL 后重返不重复拉起仍存活服务、不杀无关/外部进程；可核对原任务；归属不明时拒绝接管并提示；新实例不因 PID 复用误接管 |

## 4. unknown 的处理边界

“恢复”分四种操作，不能混为自动重试：

1. **恢复连接**：重新建立 Hub/Edge 传输，不调用模型。
2. **恢复观察**：只读定位原 Session/Message，继续收集原执行事件。
3. **恢复终态**：依据原轮次的完成/中断证据更新状态与释放占位，保留对账来源和时间。
4. **重新执行**：本轮不自动实施；用户提出新需求也必须先满足原资源可接单条件，不能绕过 unknown。

缺绑定、原生记录消失、目录/身份不符、只有“接口可达/无等待”而无轮次终态证据，均不足以认定执行完成。仅当完成/中断或所绑定执行确已停止的证据充分且两端台账一致时释放占位；不提供直接改数据库或无条件“强制清空 unknown”按钮。

原生会话数据不可恢复时，显示限制和核对步骤，保留旧历史；不得用新 Session 冒充恢复。I03A 的旧 unknown 若证据不足仍会被保留，本轮不承诺任意历史任务都能恢复。
