# I02 需求规格

2026-10-08：用户已确认范围并批准进入开发。本轮目标为通过 CLI 在固定项目目录中使用一个真实 OpenCode Agent，完成分析、修改、测试与结果查询。依据 [确认提案](proposal.md)，六项需求不扩大到完整恢复与通用控制。

| 需求 | 业务规则 | 验收 |
| --- | --- | --- |
| F01 配置检查 | 支持本机 OpenCode 2；固定已有项目目录；认证存文件；检查可用模型；失败指出配置项 | 有效配置通过；无目录、无凭据、版本不兼容、无模型分别可识别 |
| F02 真实提交 | 沿用用户身份、allowlist、请求幂等与单 Agent 串行；每任务新会话；提交前保存会话/消息绑定 | 两任务会话不同；同键相同输入提交五次只执行一次；异内容冲突 |
| F03 可读观察 | run --watch 和 task --watch 展示状态、实际工具活动、回答及等待；JSON 保留机器查询 | 人工能辨认阶段；最终回答对应原生执行；观察退出不取消任务 |
| F04 修改与等待 | 原生执行环境固定；文件和测试由 OpenCode 工具完成；等待提供本地操作入口 | 示例修改、实际测试和真实等待处理均有证据 |
| F05 简化启动/历史 | init 生成配置；up 组合启动本机服务；doctor 检查；重启查已保存结果 | 两个终端完成使用；停止只处理自身进程；历史丢失零 |
| F06 异常保护 | API 接收不是完成；明确拒绝或原生失败才 failed；断线、超时、干扰或不明中断为 unknown；不重投 | 不虚报成功、不自动重复 Prompt；旧访问和持久化规则保留 |

本地 native 操作入口需要操作者持有 Edge 配置与原生密码文件，并先经过 Hub 的任务所有权查询。它只处理该任务会话中当前等待的权限和表单，不作为远程通用回复 API。只支持单次同意或拒绝，不增加永久授权命令。

任务状态继续使用 I01 的六种状态；等待作为 running 的附加信息，不等同于成功。unknown 保留占位，不能通过新建请求绕过不明执行。本轮不实现 unknown 自动恢复或释放。

查询回答有 60,000 字节的原生适配器上限，超过时明确标注截断并指向原生会话。真实配置将 Hub 事件上限调到 64 KiB，正常文本不会沿用 I01 的 4 KiB 默认截断。性能记录实测值，不承诺模型响应 SLA。

会话续接、完整重传对账、自动故障恢复、远程统一回复与取消属于 I03；看板属于 I04。原生工具本身的项目隔离与模型配置由 OpenCode 管理，固定目录不是额外文件系统沙箱。

详细测试场景与证据在 [测试记录](testing.md)维护；开发完成和真实验收完成必须分别报告。
