# I04E：Windows Claude 进程探测异常

交付日期：2026-10-10。桌面版本：0.4.5。

## 问题与定位

用户看到 Claude 工具卡片显示“机器不可用 / spawn UNKNOWN”。Windows 在无法启动原生文件时，Node execFile 可同步抛出 UNKNOWN。原来的探测只处理回调错误，没有捕获同步异常，导致 ClaudeHost snapshot 失败，MachineRouter 将整台机器标为离线。

使用隔离的无效 Windows 原生文件，已复现同样的调用栈，见 [修复前证据](../../../artifacts/I04E-spawn-before.json)。这证明异常处理路径有缺陷；不代表用户当时的安装一定损坏。当前日常 Claude 安装可以正常返回 2.1.296，现场检查中机器在线，因此无法追溯当时具体是文件更新、系统拦截还是其他瞬时启动问题。

## 修复行为

- 版本和认证探测显式使用稳定的用户目录，避免继承便携启动器的临时目录。
- 同步启动异常与回调错误均成为工具健康检查结果，不使本地机器 snapshot 失败。
- 失败的已发现安装保留在工具列表，显示可读说明及原始错误码；项目实例显示具体启动失败原因。
- 安装恢复后，后续元数据检查恢复可用。检查不调用模型、不重放请求；原任务、未知占用保护及模型覆盖保持原有规则。
- 保留用户当前 Windows Claude 模型设置，本次未修改工具全局配置、凭据或实例模型。

## 使用

关闭旧窗口后打开 AgentBridge-0.4.5-Windows-x64.exe。机器在线与工具可执行分别显示。若仍有启动失败，可根据错误码检查 Windows 原生 Claude 安装并重新扫描；模型权限失败需另行检查实例模型，两者不能混为一谈。
